# 规则定义编辑页设计文档 v1

## 1. 文档定位

本文档用于正式收口新的规则定义编辑体验。

当前不再沿用“变量管理大表单 + 表达式文本框”的思路，而是切换为：

- 规则基础信息
- 用户开关控制
- 周期调度配置
- 可视化公式画布
- 保存

本文档主要对应：

- `AttributeManagementRouteState.RuleEditor`
- `RuleWorkbenchPage`
- `RuleEditorDraftUiModel`
- 后续规则 AST / 画布模型

---

## 2. 结论先行

当前可以正式固定的结论如下：

1. 规则编辑页的核心不再是“变量管理”，而是“可视化公式画布”。
2. 用户在画布上拖入的主要对象只有两类：
   - 空槽位
   - 计算符 / 函数块
3. 空槽位放下后，必须立即弹出配置框，要求用户补齐槽位定义。
4. 槽位是规则正式模型的一部分，仍然落库到 `slots`，不是临时 UI 元素。
5. “规则类型”不再是规则编辑页的核心概念，前端不再暴露该配置。
6. `RuleComputationType` 暂时只保留为兼容字段，第一阶段统一按 `CUSTOM` 处理。
7. “始终运行”不再作为用户可见配置项展示。
8. “启用控制”只表示：是否允许在物品页暴露规则启停开关。
9. 周期调度不再使用普通文本输入，而是升级为“日历规则编辑器”。
10. 调度事件在设计上默认会生成日历事件，由后续运行器消费执行。

---

## 3. 页面定位

规则定义编辑页负责定义“规则母版”。

它负责：

- 定义规则名称与说明
- 定义是否允许用户开关控制
- 定义周期调度规则
- 在画布上定义公式结构
- 定义输入槽位与输出槽位
- 定义槽位值来源、值类型、方向
- 保存前做结构校验

它不负责：

- 绑定某个具体物品的属性
- 直接查看某个物品上的运行结果
- 管理某条规则实例当前是否缺槽位
- 充当通用低代码流程平台

固定原则：

- `编辑页负责定义规则母版`
- `物品页负责绑定规则实例`
- `运行器负责消费规则与调度事件`

---

## 4. 当前正式设计方向

### 4.1 去掉旧的“变量管理”主视角

规则编辑页不再采用：

- 先堆一大段变量表单
- 再写一段表达式

因为这种方式的问题很明显：

- 用户对公式结构没有直觉
- 槽位、计算符、输入输出关系不够可视化
- 周期规则、条件规则、派生规则都不容易理解

新的页面重点是：

- 用户先看见一个画布
- 在画布上摆放槽位与计算符
- 再对槽位逐个补配置

### 4.2 画布才是规则结构的主视图

规则的核心心智统一为：

- 规则就是一个由槽位和计算块组成的公式结构

因此页面主视图必须是画布，不再是长表单。

---

## 5. 页面信息架构

规则编辑页建议固定为以下结构：

```text
规则定义编辑页
- 顶部栏
  - 返回
  - 页面标题
  - 保存
- 基本信息
  - 规则名称
  - 规则说明
- 启用控制
  - 是否允许用户控制启停
  - 启用文案
  - 停用文案
  - 开关挂载锚点说明
- 周期调度
  - 是否启用周期调度
  - 调度规则来源
  - 日历规则编辑器 / 槽位来源配置
  - 事件标题模板
  - 去重策略
- 可视化公式画布
  - 素材栏
  - 画布区
  - 槽位配置弹窗
  - 节点提示 / 校验反馈
```

固定原则：

- 规则编辑页里不再单独出现“变量管理”大区块
- 槽位配置通过画布上的节点交互完成
- 公式关系通过画布可视化呈现

---

## 6. 基本信息设计

### 6.1 保留项

基本信息区保留：

- 规则名称
- 规则说明

### 6.2 去掉项

以下内容不再在编辑页中展示为主要输入项：

- 规则类型
- 自定义 / 求和 / 差值 / 平均值等旧分类选择
- “运行时机 当前编辑页先用……”这类过渡说明

### 6.3 关于规则类型的正式结论

当前正式结论：

- `RuleComputationType` 继续保留在数据层
- 但不再作为编辑页的用户核心配置项
- 第一阶段前端统一按 `CUSTOM` 处理

如果后续仍需要分类能力，应改为：

- 模板分类
- 标签分类
- 管理页分组

而不是拿它驱动规则结构本身。

---

## 7. 启用控制设计

### 7.1 正式语义

“启用控制”现在只解决一件事：

- 这条规则是否需要在物品页向用户暴露启停开关

它不是：

- 运行时机
- 触发方式
- 规则类型

### 7.2 页面表现

编辑页中不再显示：

- `始终运行`
- `用户开关控制`

这样的二选一枚举。

改为：

- 一个明确的能力开关：
  - `允许用户在物品页控制此规则`

当关闭时：

- 规则默认启用
- 不暴露开关

当开启时：

- 展开补充配置：
  - 启用态文案
  - 停用态文案
  - 默认启用状态
  - 锚点槽位

### 7.3 锚点说明

锚点仍然用于表达：

- 物品页中的规则开关应该更贴近哪个属性显示

但它不在规则定义页里做复杂预览，只做配置说明。

---

## 8. 周期调度设计

### 8.1 正式语义

当规则开启周期调度后：

- 系统应为其生成日历事件
- 后续由运行器消费这些事件来执行规则

因此：

- “生成日历事件”不再是一个额外可选项
- 它是周期调度的一部分

### 8.2 调度规则来源

周期调度配置固定支持两种来源：

1. 手动配置日历规则
2. 来自槽位

### 8.3 手动配置日历规则

当用户选择“手动配置日历规则”时，应打开一个类似日历产品的调度编辑器。

建议结构：

- 开始时间
- 是否包含具体时分
- 重复频率
  - 每日
  - 每周
  - 每月
  - 每年
  - 自定义
- 重复间隔
- 每周重复日
- 每月重复方式
  - 固定日期
  - 第 N 个星期几
- 结束条件
  - 永不结束
  - 截止日期
  - 发生 N 次
- 时区

### 8.4 来自槽位

当用户选择“来自槽位”时，画布中的槽位可以承担：

- 开始时间
- 周期单位
- 周期间隔
- 结束条件
- 时区

也就是说，不再只是简单地选“哪个槽位作为调度值”，而是按调度结构进行映射。

### 8.5 周期调度的最小建模建议

设计文档层先固定以下概念：

- `scheduleSourceMode`
  - `MANUAL_CALENDAR_RULE`
  - `SLOT_DRIVEN`
- `manualScheduleRule`
  - 结构上接近 recurrence rule
- `slotDrivenSchedule`
  - 用多个槽位分别承载时间、周期、结束条件等
- `scheduleEventConfig`
  - 事件标题模板
  - 去重策略

## 9. 可视化公式画布设计

### 9.1 画布定位

画布是规则结构的主编辑器。

它负责：

- 展示公式结构
- 接纳拖拽对象
- 让用户配置槽位
- 让用户建立计算关系
- 实时提示缺失配置与类型问题

### 9.2 用户可拖拽对象

第一阶段可拖拽对象固定为：

1. 空槽位
2. 计算符
3. 函数块
4. 常量块

其中最核心的是：

- 空槽位
- 计算符

### 9.3 空槽位放下后的配置弹窗

空槽位放下后，必须立刻弹出配置框。

弹窗至少包含：

- 变量名称
- 槽位方向
  - 输入
  - 输出
- 值来源
  - 系统级变量
  - 外部输入
  - 固定值
- 值类型
  - 文本
  - 数值
  - 日期
  - 布尔
  - 选择
  - 周期单位

补充说明：

- `系统级变量`
  - 值来自整个 App 的系统变量
- `外部输入`
  - 当前在规则定义时没有具体值
  - 后续在物品规则绑定时由属性或物品级变量提供值
- `固定值`
  - 在规则定义阶段就写死具体值

### 9.4 计算符与函数块

计算符至少包括：

- `+`
- `-`
- `*`
- `/`
- `%`
- `>`
- `<`
- `>=`
- `<=`
- `==`
- `!=`
- `&&`
- `||`

函数块至少包括：

- `if`
- `coalesce`
- `min`
- `max`
- `round`
- 日期 / 周期函数

### 9.5 连接关系

第一阶段建议采用：

- 从左到右解析的单行 / 多行公式流

也就是说：

- 用户拖入槽位与计算符后
- 画布默认按从左到右顺序建立解析关系

这样实现成本更可控，也更容易让用户理解。

后续再考虑：

- 连线式连接
- 分支式连接
- 多输出分叉

### 9.6 画布节点的提示系统

画布上的节点必须通过形状、颜色、角标或文案提示当前状态。

建议至少区分：

1. 未配置槽位
2. 已配置但缺少必要字段
3. 输入槽位
4. 输出槽位
5. 系统变量槽位
6. 固定值槽位
7. 类型不兼容
8. 当前被调度配置引用

推荐视觉方向：

- 颜色区分输入 / 输出
- 边框或角标提示未完成配置
- 小标签提示值类型
- 小图标提示值来源

### 9.7 公式画布与正式模型的关系

画布不是新的运行时主模型。

正式模型依然是：

- `RuleDefinition`
- `RuleSlotDefinition`
- `RuleExpressionDefinition`
- `RuleOutputStrategyDefinition`

画布层只是新的编辑方式。

保存时需要完成：

- 画布槽位节点 -> `RuleSlotDefinition`
- 画布结构 -> `RuleExpressionDefinition`
- 输出节点 -> `RuleOutputStrategyDefinition`

---

## 10. 校验规则

规则编辑页至少要提供以下校验：

1. 规则名称不能为空
2. 画布中至少有一个输入槽位
3. 画布中至少有一个输出槽位
4. 所有槽位必须完成最小配置
5. 画布结构必须可解析
6. 输出槽位必须有明确输出目标语义
7. 若开启用户开关控制，必须补齐开关文案
8. 若开启周期调度，必须补齐完整调度规则

提示方式建议分为：

- 阻止保存的错误
- 允许保存的提醒
- 普通说明

---

## 11. 第一阶段固定边界

### 11.1 本轮必须做

1. 去掉规则类型编辑入口
2. 去掉“运行时机 当前编辑页先用……”说明
3. 去掉旧的变量管理大区块
4. 新增启用控制能力开关
5. 新增周期调度规则编辑器
6. 新增可视化公式画布
7. 支持空槽位拖入后配置
8. 支持画布节点状态提示
9. 保存时继续回写现有规则正式模型

### 11.2 本轮先不做

1. 完整自由连线系统
2. 无限画布缩放和平移
3. 多人协作编辑
4. 通用低代码流程引擎
5. 复杂多分支执行图

---

## 12. 最终结论

当前规则定义编辑页的正式设计如下：

1. 规则编辑页的主视角从“变量管理”切换为“可视化公式画布”。
2. 规则类型不再作为用户核心配置项展示，前端统一按自定义规则处理。
3. 启用控制只表达“是否在物品页暴露规则开关”，不再展示“始终运行”选项。
4. 周期调度升级为日历规则编辑器，而不是文本输入框。
5. 调度事件默认会生成日历事件，由后续运行器消费执行。
6. 用户通过拖拽空槽位、计算符、函数块来组装规则。
7. 空槽位必须通过弹窗补齐方向、值来源、值类型等正式配置。
8. 画布节点需要明确提示输入输出、值类型、值来源与未完成状态。
9. 保存结果继续回写到现有规则正式模型，保证和物品绑定页、运行器链路保持一致。

## 13. 可拖拽画布实现方案

### 13.1 画布结构

规则编辑画布由以下部分组成：

1. **素材栏（Palette）**：
   - 空输入槽位
   - 空输出槽位
   - 系统变量槽位
   - 固定值槽位
   - 算术运算符（+、-、*、/、%）
   - 比较运算符（>、<、>=、<=、==、!=）
   - 逻辑运算符（&&、||、!）
   - 函数块（if、coalesce、dateDiff、cycleCount 等）

2. **画布区（Canvas）**：
   - 可滚动、可缩放的无限画布
   - 用户从素材栏拖入节点
   - 节点显示在画布指定位置
   - 节点间可以通过连线表示计算依赖

3. **节点配置弹窗**：
   - 点击空槽位节点后弹出
   - 配置：变量名、变量标识、方向（输入/输出）、值类型、值来源
   - 值来源：系统级变量、外部输入、固定值
   - 保存后节点显示配置结果

### 13.2 节点类型与视觉设计

**槽位节点**：
- 未配置：浅红边框 + "待配置"标签
- 输入槽位：蓝色容器 + "输入"标签
- 输出槽位：绿色容器 + "输出"标签
- 系统变量：紫色容器 + "系统"标签 + 系统变量名
- 固定值：橙色容器 + "固定"标签 + 固定值预览

**计算符节点**：
- 圆形或方形容器
- 显示符号（+、-、*、/、>、<、&&、||等）
- 左右两侧有连接点

**函数节点**：
- 矩形容器
- 显示函数名（if、coalesce、dateDiff等）
- 多个输入连接点（根据函数参数数量）
- 一个输出连接点

### 13.3 拖拽交互

1. **从素材栏拖入**：
   - 用户长按素材栏中的节点
   - 拖动到画布区
   - 松手后节点出现在画布指定位置
   - 如果是空槽位，立即弹出配置框

2. **画布内拖动**：
   - 长按已有节点
   - 拖动到新位置
   - 松手后节点移动到新位置
   - 连线自动重新绘制

3. **节点连接**：
   - 点击节点输出点
   - 拖动到另一个节点输入点
   - 松手后建立连接
   - 连线显示计算流向

4. **节点删除**：
   - 长按节点弹出菜单
   - 选择删除
   - 删除节点及相关连线

### 13.4 技术实现要点

**Compose 实现**：
- `Modifier.pointerInput` + `detectDragGestures` 实现拖拽
- `Canvas` 组件绘制连线
- `offset` 管理节点位置
- `LazyColumn` / `LazyRow` 实现素材栏
- `AlertDialog` / `ModalBottomSheet` 实现配置弹窗

**数据模型**：
``kotlin
data class CanvasNode(
    val id: String,
    val type: CanvasNodeType, // SLOT, OPERATOR, FUNCTION
    val x: Float,
    val y: Float,
    val slotConfig: RuleSlotDraftUiModel?, // 仅槽位节点有
    val operatorSymbol: String?, // 仅运算符节点有
    val functionName: String?, // 仅函数节点有
)

data class CanvasConnection(
    val id: String,
    val fromNodeId: String,
    val fromPort: String,
    val toNodeId: String,
    val toPort: String,
)

enum class CanvasNodeType {
    SLOT, OPERATOR, FUNCTION
}
``

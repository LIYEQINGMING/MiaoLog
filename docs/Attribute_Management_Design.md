# 属性管理设计方案

## 1. 文档目的

本文档用于固定"自定义属性管理"的统一设计方向，作为后续以下模块的依据：

- 新增/修改页中的属性选择交互
- "我的"页面中的属性管理页
- 自定义属性的创建、编辑、删除流程
- 内置属性与自定义属性的统一管理

---

## 2. 问题分析

### 2.1 当前存在的问题

1. **新增/修改页属性选择问题**
   - 仅允许选择已有的属性，不能直接创建新属性
   - 缺少快速创建自定义属性的入口
   - 属性选择与属性管理脱节

2. **缺少统一的属性管理入口**
   - 当前没有独立的属性管理页面
   - 用户无法统一查看和管理所有自定义属性
   - 无法查看属性的使用情况

3. **与分类/标签管理不一致**
   - 分类和标签都有独立管理页面
   - 属性应该与它们保持一致的架构
   - 都应该放在"我的"页面中

### 2.2 需要满足的目标

1. 属性管理应该与分类管理、标签管理一样，放在"我的"页面里
2. 允许用户统一管理所有的自定义属性
3. 在新增和修改页的属性选择栏中，允许直接创建新属性
4. 系统内置属性和用户自定义属性应该统一展示和管理

---

## 3. 核心设计理念

### 3.1 属性分类

系统中的属性分为两类：

1. **系统内置属性**
   - 由系统提供的预设属性
   - 完全只读，不可编辑
   - 不可删除
   - 例如：购入价格、总价、订阅价格等

2. **用户自定义属性**
   - 用户自己创建的属性
   - 可以完全编辑
   - 可以删除
   - 支持多种类型：文本、数字、日期、布尔值、价格

### 3.2 统一管理原则

- 系统内置属性和用户自定义属性在同一列表中展示
- 通过标签或视觉区分内置/自定义属性
- 内置属性有"系统"标识，不可删除
- 自定义属性有完全的编辑和删除权限

---

## 4. "我的"页面中的属性管理

### 4.1 页面入口

在"我的"页面中，新增入口：

```
我的
├── 分类管理
├── 标签管理
├── 属性管理 ← 新增
├── ...
```

### 4.2 属性管理页设计

#### 4.2.1 页面结构

属性管理页采用列表视图，包含：

1. **顶部搜索栏**
   - 搜索属性名称
   - 筛选属性类型
   - 筛选内置/自定义属性

2. **属性列表**
   - 每个属性作为一个卡片项
   - 显示：属性图标、名称、类型、使用数量
   - 内置属性显示"系统"标签
   - 自定义属性可滑动删除

3. **操作按钮**
   - 底部悬浮添加按钮
   - 创建新属性

#### 4.2.2 属性卡片结构

```
┌─────────────────────────────────────┐
│ 📦 购入价格              [系统]    │
│ 类型：价格 | 使用：42 个物品       │
└─────────────────────────────────────┘
```

```
┌─────────────────────────────────────┐
│ 🔧 保养费用                        │
│ 类型：价格 | 使用：3 个物品        │
├─────────────────────────────────────┤
│ [编辑]  [删除]                      │
└─────────────────────────────────────┘
```

#### 4.2.3 内置属性与自定义属性的区别

| 特性 | 系统内置属性 | 用户自定义属性 |
|------|-------------|---------------|
| 删除 | ❌ 不可删除 | ✅ 可删除 |
| 编辑 | ❌ 完全只读 | ✅ 完全可编辑 |
| 标识 | 显示"系统"标签 | 无特殊标签 |
| 创建 | 系统预置 | 用户创建 |

### 4.4 创建新属性流程

#### 4.4.1 属性类型选择

创建新属性时，首先选择属性类型：

1. **文本** - 短文本或长文本
2. **数字** - 数值，支持单位
3. **日期** - 日期选择
4. **布尔值** - 开关/复选框
5. **价格** - 完整的价格属性块

#### 4.4.2 价格属性创建

选择"价格"类型后，配置：

1. **基本信息**
   - 属性名称
   - 价格语义角色（购入价格、总价、定金、尾款、订阅价格、当前估值、自定义价格）
   - 图标

2. **动作配置**
   - 支持哪些动作（计入总价、参与均价计算、参与日均价值计算）
   - 默认动作值

3. **周期规则**
   - 是否支持周期规则
   - 默认周期配置

4. **默认值**
   - 默认币种

## 5. 新增/修改页属性选择增强

### 5.1 属性选择器改造

在属性选择器（EditFieldsFragment）中，增加：

1. **新建属性入口**
   - 在属性列表顶部添加"创建新属性"入口
   - 点击后弹出属性创建对话框

2. **快速创建属性**
   - 支持在属性选择时直接创建
   - 创建后自动选中该属性

### 5.2 属性创建对话框

属性创建对话框包含：

1. **属性名称** - 输入框
2. **属性类型** - 类型选择器
3. **快速创建**按钮 - 确认创建

对于价格类型，还可以快速配置：
- 默认动作
- 是否支持周期

---

## 6. 删除属性规则

### 6.1 删除自定义属性

删除自定义属性时，遵循以下规则：

1. **未被使用的属性**
   - 直接删除，无需确认

2. **已被使用的属性**
   - 显示二次确认对话框
   - 提示："该属性已被 X 个物品使用，确定删除吗？"
   - 删除后，物品中的该属性值也会被删除

### 6.2 系统内置属性

- 不允许删除
- 显示"系统属性，不可删除"提示

### 8.1 优先级 1（核心功能）

1. ✅ 属性管理页面入口（放在"我的"页面）

3. ✅ 创建新自定义属性

### 8.2 优先级 2（增强功能）

1. 属性搜索和筛选

## 9. 与现有设计的一致性

属性管理设计遵循以下原则，与现有系统保持一致：

1. **页面位置一致** - 与分类管理、标签管理一样放在"我的"页面
2. **UI风格一致** - 使用相同的卡片、列表、按钮设计
3. **交互模式一致** - 左滑删除、编辑对话框、确认流程
4. **数据结构一致** - 复用现有的 CustomAttributeDefinitionEntity
5. **命名规范一致** - 使用中文界面，符合用户习惯

---

## 10. 总结

属性管理设计方案核心要点：

1. **属性管理放在"我的"页面**，与分类、标签管理并列
2. **统一管理内置和自定义属性**，通过视觉标识区分
3. **内置属性完全只读**，不可删除也不可编辑
4. **自定义属性完全可编辑**，可以完全可删除
5. **在属性选择器中支持直接创建**新属性
6. **第一阶段实现核心功能**，后续逐步完善

### 10.1 为什么内置属性完全只读

采用内置属性完全只读的设计，原因如下：

1. **系统稳定性**：避免用户不小心修改内置属性定义导致系统功能异常
2. **一致性保证**：确保系统内置属性有固定的语义和行为保持一致
3. **简化理解**：用户不需要区分"部分编辑"、"完全编辑"等复杂概念
4. **最佳实践**：参考主流产品中，系统预置内容通常都是只读的
5. **灵活性保留**：用户如果需要自定义，可以创建全新的自定义属性

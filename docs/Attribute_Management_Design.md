# 属性管理页面设计文档

## 1. 文档目的

本文档用于固定“属性管理页”的产品方案，作为后续以下模块的统一依据：

- “我的”页面中的属性管理入口与信息架构
- 属性管理页的双视图设计：属性视图与模板视图
- 属性定义与属性模板的浏览、搜索、筛选、创建、编辑、删除交互
- 新增页、编辑页中“轻量使用属性”和管理页中“完整治理属性”的分工
- 基于 `docs/Attribute_Modeling_Spec.md` 与 `docs/Attribute_Template_Spec.md` 的页面落地方式

本文档聚焦的是：

- `属性管理页本身怎么设计`
- `属性视图和模板视图各自负责什么`
- `属性管理页和新增/编辑页怎么协同`

属性模型本体与模板边界，统一以以下文档为基础：

- [Attribute_Modeling_Spec.md](file:///D:/BaiduSyncdisk/CodeSpace/MiaoLog/docs/Attribute_Modeling_Spec.md)
- [Attribute_Template_Spec.md](file:///D:/BaiduSyncdisk/CodeSpace/MiaoLog/docs/Attribute_Template_Spec.md)

## 2. 为什么需要独立的属性管理页

虽然新增页和编辑页中已经存在属性补充与属性选择需求，但“使用属性”和“治理属性”是两件不同的事。

当前需要独立属性管理页，主要因为：

1. 用户需要统一查看整个系统中可复用的属性定义，而不是只在某个物品表单里被动看到。
2. 用户需要理解系统到底提供了哪些模板、哪些模板适合创建什么属性。
3. 新增页和编辑页的职责应是“快速录入和编辑物品”，不应承担完整的属性治理工作。
4. 分类、标签、属性都属于物品体系的全局基础能力，应该统一收口在“我的”页面里。

因此这里固定一条原则：

- `属性管理属于全局治理能力，不属于某个单一物品的局部编辑能力`

## 3. 页面定位

### 3.1 入口位置

“我的”页面中应增加：

- `属性管理`

并与以下入口并列：

- `分类管理`
- `标签管理`

推荐结构：

```text
我的
- 分类管理
- 标签管理
- 属性管理
```

### 3.2 页面职责

属性管理页负责：

- 查看全部属性定义
- 查看全部基础模板与基石模板
- 搜索属性和模板
- 按来源、类型、模板分类等维度筛选
- 查看属性来源、模板来源、使用数量、规则参与摘要
- 从模板创建属性
- 编辑自定义属性
- 删除自定义属性
- 作为新增页、编辑页中“去管理属性”的全局入口

属性管理页不负责：

- 直接编辑某件物品上的属性值
- 在这里替代新增页或编辑页的表单录入流程
- 让用户自由创建任意新规则类型
- 把属性系统做成任意公式引擎或低代码平台

## 4. 核心设计原则

### 4.1 管理对象是“属性定义 + 属性模板”

属性管理页的核心治理对象不再只有属性定义，而是两类对象：

1. 属性定义
2. 属性模板

这意味着属性管理页必须同时回答两类问题：

- 我当前有哪些属性正在被使用
- 系统当前提供了哪些模板作为属性创建母板

### 4.2 第一阶段固定为双视图

属性管理页第一阶段固定为两个视图：

1. `属性视图`
2. `模板视图`

不在第一阶段继续扩展第三个“规则视图”。

原因是：

1. 这已经足以覆盖当前最核心的两层对象：属性定义与属性模板。
2. 信息架构足够清晰，不会一上来就过重。
3. 更符合移动端治理页面的复杂度控制。

### 4.3 与分类管理页保持同一视觉语法

属性管理页应尽量沿用分类管理页的视觉与交互语言：

- 顶部标题
- 搜索
- 列表卡片
- 更多操作菜单
- 底部新增入口
- 空状态与搜索状态分离

这样用户更容易理解：

- `分类管理`
- `标签管理`
- `属性管理`

属于同一组全局治理页面。

### 4.4 不把内部开放等级直接暴露给用户

属性系统开放等级属于内部设计共识，不直接显示给用户。

对用户更合适的表达是：

- `属性`
- `模板`
- `从模板创建`
- `高级设置`

而不是：

- Level 1 / Level 2 / Level 3

## 5. 页面总体结构

### 5.1 顶部区域

页面顶部建议包含：

- 页面标题：`属性管理`
- 视图切换：
  - `属性`
  - `模板`
- 搜索入口

说明：

- 视图切换是第一阶段页面结构中的核心变化
- 搜索内容应随当前视图切换

### 5.2 主内容区

主内容区根据当前视图不同，展示不同列表：

- 属性视图 -> 属性定义列表
- 模板视图 -> 属性模板列表

两种视图都应支持：

- 筛选状态栏
- 列表内容
- 空状态
- 搜索无结果状态

### 5.3 底部操作

页面底部或悬浮按钮建议根据当前视图显示不同主操作：

- 属性视图：
  - `新建属性`

- 模板视图：
  - `从模板创建属性`

这样可以让主操作与当前视图语义保持一致。

## 6. 属性视图设计

### 6.1 视图职责

属性视图负责治理“属性定义”。

这里看的是：

- 系统中有哪些属性定义
- 每个属性来自哪个模板
- 该属性当前被多少物品使用
- 该属性当前启用了哪些统计参与项

### 6.2 列表项建议展示的信息

每个属性卡片建议展示：

- 属性图标
- 属性名称
- 来源标签
  - 系统
  - 自定义
- 类型标签
  - 文本
  - 数字
  - 日期
  - 布尔
  - 单选
  - 多选
  - 价格
- 模板来源
- 使用数量
- 规则参与摘要

### 6.3 卡片示意

系统属性示意：

```text
购入价格      [系统] [价格]
来源模板：购入价格模板
参与：总资产 / 平均成本
使用：42 个物品
```

用户自定义属性示意：

```text
收藏编号      [自定义] [文本]
来源模板：文本模板
规则：无
使用：8 个物品
```

### 6.4 规则参与摘要规则

属性视图中的摘要不展示规则计算过程，只展示该属性当前启用了哪些参与项。

例如：

- `参与：总资产`
- `参与：总资产 / 平均成本`
- `规则：无`

这样可以帮助用户快速理解字段将被系统用在什么口径中，而不会让卡片过重。

### 6.5 点击行为

点击属性卡片时：

- 默认进入属性详情或属性编辑页

第一版也可用更轻量的方式：

- 点击弹出属性编辑对话框

但对于价格属性这类复杂定义，更推荐独立详情/编辑页。

### 6.6 更多操作

每个属性卡片应提供“更多操作”入口，推荐包括：

- 查看详情
- 编辑属性
- 删除属性

其中：

- 系统内置属性不显示删除
- 系统内置属性默认不允许编辑核心定义

---

## 7. 模板视图设计

### 7.1 视图职责

模板视图负责治理“属性模板”。

这里看的是：

- 系统中有哪些模板
- 模板属于基础模板还是基石模板
- 模板的属性类型是什么
- 模板的领域类型是什么
- 模板支持哪些统计规则集合
- 模板派生出了多少个属性定义

### 7.2 列表项建议展示的信息

每个模板卡片建议展示：

- 模板图标
- 模板名称
- 模板分类
  - 基础模板
  - 基石模板
- 属性类型
- 领域类型
- 支持的统计规则摘要
- 派生属性数量

### 7.3 卡片示意

价格基石模板示意：

```text
购入价格模板      [基石模板] [价格]
领域：购入价格
支持：总资产 / 平均成本 / 日均价值
派生属性：12 个
```

基础模板示意：

```text
文本模板          [基础模板] [文本]
领域：通用字段
支持：无统计规则
派生属性：28 个
```

### 7.4 点击行为

点击模板卡片时：

- 默认进入模板详情页

模板详情页建议重点展示：

- 模板定义
- 属性类型
- 领域类型
- 支持的统计规则集合
- 支持的高级设置
- 典型创建用途
- 从该模板创建属性的入口

### 7.5 更多操作

第一阶段模板视图的更多操作建议保守收口。

推荐包括：

- 查看模板详情
- 从模板创建属性

第一阶段不建议开放：

- 用户编辑系统模板结构
- 用户删除系统模板
- 用户新建任意模板

## 8. 搜索与筛选

## 8.1 搜索行为

搜索应跟随当前视图切换：

- 在属性视图中，按属性名称、属性类型、模板名搜索
- 在模板视图中，按模板名称、模板分类、属性类型、领域类型搜索

例如：

- 搜索 `价格`
  - 属性视图应命中购入价格、总价、自定义价格等属性
  - 模板视图应命中购入价格模板、总价模板、空白价格模板等模板

## 8.2 属性视图筛选

属性视图建议支持以下筛选：

- 来源筛选
  - 全部
  - 系统属性
  - 自定义属性

- 类型筛选
  - 全部类型
  - 文本
  - 数字
  - 日期
  - 布尔
  - 单选
  - 多选
  - 价格

- 模板筛选
  - 全部模板
  - 基础模板来源
  - 基石模板来源
  - 指定模板

## 8.3 模板视图筛选

模板视图建议支持以下筛选：

- 模板分类
  - 全部
  - 基础模板
  - 基石模板

- 属性类型
  - 全部类型
  - 文本
  - 数字
  - 日期
  - 布尔
  - 单选
  - 多选
  - 价格

- 领域类型
  - 全部领域
  - 通用字段
  - 购入价格
  - 总价
  - 当前估值
  - 定金
  - 订阅价格

## 9. 创建流程

## 9.1 属性视图中的创建入口

属性视图中的 `新建属性` 是完整治理入口。

它和新增页、编辑页中的“轻量创建属性”不是同一层能力。

固定分工如下：

- 新增页 / 编辑页
  - 负责“轻量使用属性”
  - 支持快速创建

- 属性管理页
  - 负责“完整定义属性”
  - 支持通过模板完成标准化创建

### 9.1.1 新建属性推荐流程

推荐流程如下：

1. 选择基础模板或基石模板
2. 配置属性名、图标、输入方式、默认值
3. 调整类型配置
4. 如果模板支持规则参与项，则展示可选开关
5. 如果用户打开某项规则参与，则按需展示高级设置
6. 保存属性定义

## 9.2 模板视图中的创建入口

模板视图中的主操作为：

- `从模板创建属性`

这条路径的优势是：

- 用户先看到模板边界
- 再决定是否基于该模板创建
- 更适合价格这类复杂属性

### 9.2.1 模板创建流程

推荐流程如下：

1. 进入模板详情
2. 点击 `从模板创建属性`
3. 系统带出模板默认值
4. 用户微调名称、图标、默认值和规则参与开关
5. 保存属性定义

## 10. 编辑与删除规则

## 10.1 属性定义

### 10.1.1 系统属性

系统属性默认：

- 不可删除
- 不可修改核心定义

第一阶段建议采用完全只读方案。

### 10.1.2 自定义属性

允许编辑：

- 名称
- 图标
- 输入方式
- 类型配置
- 模板允许范围内的规则参与项
- 模板允许范围内的高级设置

但必须注意：

- 不支持把一个已有属性跨类型转换
- 不支持越过模板边界添加模板未支持的规则

### 10.1.3 删除规则

删除自定义属性时，遵循以下规则：

1. 未被使用
   - 可以直接删除

2. 已被使用
   - 必须二次确认
   - 需要明确提示影响范围

建议提示文案：

- `该属性已被 12 个物品使用，删除后这些物品中的该属性值也会被移除，是否继续？`

## 10.2 模板

第一阶段模板以系统内置模板为主。

固定规则如下：

- 系统模板不可删除
- 系统模板不可直接编辑结构
- 系统模板可查看、可用于创建属性

说明：

- 第一阶段不做用户自定义模板治理
- 模板视图主要承担“查看模板边界”和“从模板创建属性”的职责

## 11. 与新增页和编辑页的关系

### 11.1 新增页 / 编辑页中的属性入口

新增页和编辑页中，属性相关入口应继续保留在：

- 基础信息区 `+`
- 补充信息区 `+`

这些入口的职责是：

- 为当前表单补充属性
- 轻量选择属性
- 必要时快速创建属性

### 11.2 从表单跳转到属性管理页

当用户在表单中遇到以下场景时，应支持：

- `去属性管理`

典型场景包括：

- 需要统一整理属性体系
- 需要查看属性是否来自合适的模板
- 需要完整配置价格等复杂属性
- 需要从模板重新创建标准属性

### 11.3 轻量创建与完整治理分工

固定分工如下：

- 轻量创建
  - 放在新增页 / 编辑页的属性选择面板里
  - 创建后自动选中

- 完整治理
  - 放在属性管理页里
  - 用于完整配置属性定义和查看模板边界

### 11.4 数据同步要求

属性管理页中发生以下操作后，新增页与编辑页应立即感知：

- 新建属性
- 编辑属性名称
- 编辑属性配置
- 删除属性

这样可以避免：

- 管理页已更新
- 表单里还是旧定义

## 12. 数据建模建议

属性管理页应基于以下两份文档协同实现：

- [Attribute_Modeling_Spec.md](file:///D:/BaiduSyncdisk/CodeSpace/MiaoLog/docs/Attribute_Modeling_Spec.md)
- [Attribute_Template_Spec.md](file:///D:/BaiduSyncdisk/CodeSpace/MiaoLog/docs/Attribute_Template_Spec.md)

当前页面至少需要承接以下对象：

### 12.1 属性定义对象

建议字段至少包括：

- `id`
- `name`
- `type`
- `iconName`
- `templateId`
- `isSystemBuiltIn`
- `ruleParticipationSummary`

### 12.2 模板对象

建议字段至少包括：

- `templateId`
- `templateName`
- `templateCategory`
- `attributeType`
- `domainType`
- `supportedRuleSet`
- `supportsAdvancedSettings`

### 12.3 使用数量

属性视图需要展示：

- 该属性定义被多少个物品实例引用

模板视图需要展示：

- 该模板派生出了多少个属性定义

## 13. 第一阶段落地范围

第一阶段建议完成：

1. “我的”页面增加 `属性管理` 入口
2. 属性管理页顶部双视图切换：
   - 属性
   - 模板
3. 属性视图基础列表
4. 模板视图基础列表
5. 搜索属性
6. 搜索模板
7. 属性视图的来源、类型、模板筛选
8. 模板视图的分类、类型、领域筛选
9. 从模板创建属性
10. 编辑自定义属性
11. 删除自定义属性
12. 展示属性使用数量
13. 展示模板派生属性数量

第一阶段暂不做：

- 用户自定义模板
- 编辑系统模板结构
- 独立规则视图
- 任意规则编辑器
- 批量迁移属性值

---

## 14. 与现有设计的一致性

属性管理页设计遵循以下原则，与现有系统保持一致：

1. 页面位置一致：与分类管理、标签管理一样放在“我的”页面
2. 视觉语言一致：复用分类管理页的搜索、卡片、更多操作、底部主操作入口
3. 分工一致：新增/编辑页负责使用属性，管理页负责治理属性
4. 模型一致：以“模板先行、字段与规则分层”为新主线
5. 命名一致：使用中文界面，必要时在文档中保留英文模型名用于技术对齐

---

## 15. 最终固定方案

当前可固定的属性管理页方案如下：

1. 属性管理放在“我的”页面中，作为全局基础治理能力。
2. 属性管理页第一阶段固定为两个视图：`属性视图` 与 `模板视图`。
3. 属性视图治理属性定义，模板视图治理属性模板。
4. 属性视图重点展示属性来源、类型、模板来源、规则参与摘要与使用数量。
5. 模板视图重点展示模板分类、属性类型、领域类型、支持规则集合与派生属性数量。
6. 用户创建属性应优先从模板出发，尤其是价格等复杂属性。
7. 模板视图的主入口是“从模板创建属性”，而不是直接编辑模板结构。
8. 系统内置模板和系统内置属性第一阶段都以只读为主。
9. 新增页和编辑页中的轻量创建，不替代属性管理页的完整治理能力。
10. 后续若模板体系继续扩展，可在此基础上再考虑独立模板管理页或增加规则视图，但第一阶段先严格收敛为双视图方案。

## 2. 页面定位

## 2.1 为什么需要独立页面

虽然新增页和编辑页已经存在属性补充与属性选择需求，但“使用属性”和“治理属性”是两件不同的事。

当前需要独立属性管理页，主要因为：

1. 用户需要统一查看系统中可复用的属性定义，而不是只在某个物品表单里被动看到。
2. 用户需要统一查看系统中有哪些规则定义，以及这些规则当前被哪些属性使用。
3. 用户需要理解系统当前提供了哪些模板，以及这些模板分别适合创建属性还是创建规则。
4. 新增页和编辑页的职责应是“快速录入和编辑物品”，不应承担完整的属性与规则治理工作。
5. 分类、标签、属性都属于物品体系的全局基础能力，应该统一收口在“我的”页面里。

固定原则：

- `属性管理属于全局治理能力，不属于某个单一物品的局部编辑能力`

## 2.2 入口位置

“我的”页面中应增加：

- `属性管理`

并与以下入口并列：

- `分类管理`
- `标签管理`

推荐结构：

```text
我的
- 分类管理
- 标签管理
- 属性管理
```

## 2.3 页面职责

属性管理页负责：

- 查看全部属性定义
- 查看全部规则定义
- 查看全部属性模板与规则模板
- 搜索属性、规则、模板
- 按来源、值类型、规则类型、模板类型等维度筛选
- 查看属性的模板来源、规则绑定摘要、使用数量
- 查看规则的槽位摘要、输出摘要、绑定影响范围
- 从模板创建属性
- 从规则模板创建规则
- 编辑自定义属性
- 编辑自定义规则
- 删除自定义属性
- 删除自定义规则
- 作为新增页、编辑页中的“去管理属性”全局入口

属性管理页不负责：

- 直接编辑某件物品上的属性值
- 在这里替代新增页或编辑页的表单录入流程
- 直接运行规则调试台
- 把属性系统做成任意低代码平台

## 3. 核心设计原则

## 3.1 管理对象是“属性定义 + 规则定义 + 模板”

属性管理页的核心治理对象有三类：

1. 属性定义
2. 规则定义
3. 模板

其中模板在当前阶段又分成：

- 属性模板
- 规则模板

这意味着属性管理页必须同时回答三类问题：

- 我当前有哪些属性正在被使用
- 系统当前有哪些规则正在被属性使用
- 系统当前有哪些模板可以帮助我创建属性或规则

## 3.2 第一阶段固定为三视图

属性管理页第一阶段固定为三个视图：

1. `属性视图`
2. `规则视图`
3. `模板视图`

原因是：

1. 规则在 V1 中已经是独立主模型，不再适合只挂靠在模板视图下表达。
2. 规则治理已经包含列表、详情、编辑、删除、影响分析等完整闭环。
3. 模板视图与规则视图职责不同，混在一起会继续制造语义割裂。

## 3.3 不把内部建模概念直接暴露给用户

属性系统内部存在：

- 属性模型
- 规则模型
- 属性模板
- 规则模板
- 规则绑定实例

但在用户界面中，仍应优先使用更自然的表达：

- `属性`
- `规则`
- `模板`
- `添加规则`
- `规则绑定`
- `高级设置`

而不是直接把抽象数据建模术语堆给用户。

## 3.4 与分类管理页保持同一视觉语法

属性管理页应尽量沿用分类管理页的视觉与交互语言：

- 顶部标题
- 搜索
- 列表卡片
- 更多操作菜单
- 主操作入口
- 空状态与搜索状态分离

## 4. 页面总体结构

## 4.1 顶部区域

页面顶部建议包含：

- 页面标题：`属性管理`
- 视图切换：
  - `属性`
  - `规则`
  - `模板`
- 搜索入口

说明：

- 视图切换是当前页面结构中的核心导航
- 搜索内容应随当前视图切换

## 4.2 主内容区

主内容区根据当前视图不同，展示不同列表：

- 属性视图 -> 属性定义列表
- 规则视图 -> 规则定义列表
- 模板视图 -> 模板列表

三种视图都应支持：

- 筛选状态栏
- 列表内容
- 空状态
- 搜索无结果状态

## 4.3 主操作

页面主操作建议根据当前视图显示不同入口：

- 属性视图：
  - `新建属性`
- 规则视图：
  - `新建规则`
- 模板视图：
  - `从模板创建`

其中模板视图中的 `从模板创建` 进入后，再让用户选择：

- 从属性模板创建属性
- 从规则模板创建规则

## 5. 属性视图设计

## 5.1 视图职责

属性视图负责治理“属性定义”。

这里看的是：

- 系统中有哪些属性定义
- 每个属性来自哪个属性模板
- 该属性当前被多少物品使用
- 该属性绑定了哪些规则实例
- 该属性在规则中扮演什么入口或依赖角色

## 5.2 列表项建议展示的信息

每个属性卡片建议展示：

- 属性图标
- 属性名称
- 来源标签
- 值类型标签
- 值来源标签
- 值属性摘要
- 交互方式摘要
- 模板来源
- 规则绑定摘要
- 使用数量

## 5.3 规则绑定摘要规则

属性视图中的摘要不展示规则计算过程，只展示：

- 当前属性绑定了哪些规则
- 当前属性在规则中扮演什么角色
- 是否会引入依赖补齐或派生输出

例如：

- `规则：计入总价`
- `规则：待付尾款（入口槽位：deposit）`
- `规则：周期扣费（依赖：订阅日，输出：累计总价）`

## 5.4 点击行为

点击属性卡片时：

- 默认进入属性详情页

对于绑定规则较多的属性，不建议只用轻量弹窗。

## 5.5 更多操作

每个属性卡片应提供“更多操作”入口，推荐包括：

- 查看详情
- 编辑属性
- 添加规则
- 删除属性

其中：

- 系统内置属性不显示删除
- “添加规则”进入规则绑定页，而不是规则定义编辑页

---

## 6. 规则视图设计

## 6.1 视图职责

规则视图负责治理“规则定义”。

这里看的是：

- 系统中有哪些规则定义
- 每条规则属于什么类型
- 规则有哪些输入槽位和输出槽位
- 规则当前被多少个属性使用
- 删除规则会影响哪些属性

## 6.2 列表项建议展示的信息

每个规则卡片建议展示：

- 规则图标
- 规则名称
- 来源标签
- 规则类型
- 输入槽位摘要
- 输出槽位摘要
- 绑定属性数量
- 关联属性名称摘要

## 6.3 更多操作

每个规则卡片应提供：

- 查看规则详情
- 编辑规则
- 删除规则

其中：

- 系统规则只允许查看
- 自定义规则允许编辑和删除

---

## 7. 模板视图设计

## 7.1 视图职责

模板视图负责治理“模板体系”。

这里看的是：

- 系统中有哪些属性模板
- 系统中有哪些规则模板
- 模板属于哪一类模板
- 模板的默认边界是什么
- 模板能派生出什么对象

## 7.2 列表项建议展示的信息

每个模板卡片建议展示：

- 模板图标
- 模板名称
- 模板类型
- 模板分类或规则类型
- 默认边界摘要
- 派生数量或引用数量

说明：

- 当模板是属性模板时，重点展示默认值类型、默认值属性、默认值来源、默认交互方式、默认规则绑定。
- 当模板是规则模板时，重点展示规则类型、槽位摘要、输出定义、触发方式。

## 7.3 更多操作

模板视图推荐包括：

- 查看模板详情
- 从属性模板创建属性
- 从规则模板创建规则

第一阶段不建议开放：

- 用户编辑系统模板结构
- 用户删除系统模板
- 用户新建任意模板

## 8. 搜索与筛选

## 8.1 搜索行为

搜索应跟随当前视图切换：

- 在属性视图中，按属性名称、值类型、模板名、规则名搜索
- 在规则视图中，按规则名称、规则类型、槽位 key、输出定义搜索
- 在模板视图中，按模板名称、模板类型、模板分类、规则类型搜索

## 8.2 属性视图筛选

属性视图建议支持：

- 来源筛选
- 值类型筛选
- 值来源筛选
- 规则绑定筛选

## 8.3 规则视图筛选

规则视图建议支持：

- 来源筛选
- 规则类型筛选
- 绑定情况筛选

## 8.4 模板视图筛选

模板视图建议支持：

- 模板类型筛选
- 模板分类筛选
- 规则类型筛选
- 值类型筛选

## 9. 创建流程

## 9.1 属性视图中的创建入口

属性视图中的 `新建属性` 是完整治理入口。

推荐流程如下：

1. 选择属性模板
2. 配置属性名、值类型、值属性、值来源、交互方式
3. 查看可绑定规则范围
4. 保存属性定义

## 9.2 规则视图中的创建入口

规则视图中的 `新建规则` 是规则定义治理入口。

推荐流程如下：

1. 选择是否基于规则模板创建
2. 配置规则名称、类型、槽位定义、表达式、输出策略
3. 保存规则定义

## 9.3 从属性出发添加规则

当用户在属性详情页或属性卡片上点击 `添加规则` 时，应进入：

- `规则绑定页`

这条路径用于：

- 给当前属性选择兼容规则
- 选择入口槽位
- 补齐其他槽位
- 保存规则绑定实例

固定原则：

- `新建规则` 是定义规则母版
- `添加规则` 是为当前属性创建规则绑定实例

## 10. 编辑与删除

## 10.1 属性定义

系统属性默认：

- 不可删除
- 不可修改核心定义

自定义属性允许编辑：

- 名称
- 图标
- 值类型
- 值属性
- 值来源
- 交互方式
- 允许范围内的规则绑定

删除属性时必须提示：

- 使用数量
- 规则影响范围

## 10.2 规则定义

系统规则默认：

- 不可删除
- 不可修改核心结构

自定义规则允许编辑：

- 名称
- 类型
- 槽位定义
- 表达式
- 输出策略
- 触发方式

删除规则时必须提示：

- 当前绑定属性数量
- 受影响属性名称摘要
- 删除后会自动移除相关绑定实例

## 10.3 模板

第一阶段模板以系统内置模板为主。

固定规则如下：

- 系统模板不可删除
- 系统模板不可直接编辑结构
- 系统模板可查看
- 属性模板可用于创建属性
- 规则模板可用于创建规则或理解规则边界

## 11. 与新增页和编辑页的关系

## 11.1 新增页 / 编辑页中的属性入口

新增页和编辑页中，属性相关入口应继续保留在：

- 基础信息区 `+`
- 补充信息区 `+`

这些入口的职责是：

- 为当前表单补充属性
- 轻量选择属性
- 必要时快速创建属性

## 11.2 从表单跳转到属性管理页

当用户在表单中遇到以下场景时，应支持：

- `去属性管理`

典型场景包括：

- 需要统一整理属性体系
- 需要完整配置带规则绑定的复杂属性
- 需要查看某个规则为什么会补出其他依赖属性
- 需要新建规则定义或修改规则母版

## 11.3 表单层自动补齐与管理页协同

根据当前属性模型与规则模型，新增页和编辑页在用户添加属性时，应遵循：

1. 用户选择一个属性
2. 系统将该属性加入当前物品填写清单
3. 系统读取该属性关联的规则绑定实例
4. 对每条绑定实例读取必填的属性输入槽位
5. 若依赖属性尚未存在，则自动补齐
6. 若依赖属性已存在，则复用不重复添加

因此管理页需要让用户看得见：

- 一个属性绑定了哪些规则实例
- 当前属性在规则中占据哪个槽位
- 自动补齐发生的原因是什么
- 哪些输出是只读结果，哪些会写回属性

## 12. 页面信息架构拆解

## 12.1 页面层级

属性管理页建议拆成以下层级：

### L0 全局入口

- 我的
  - 属性管理

### L1 主页面

- `属性管理主页面`
  - 顶部标题
  - 视图切换
  - 搜索
  - 筛选区
  - 列表区
  - 主操作入口

### L2 详情与创建页面

- `属性详情页`
- `属性编辑页`
- `规则详情页`
- `规则定义编辑页`
- `模板详情页`
- `从模板创建属性页`
- `从模板创建规则页`
- `规则绑定页`

### L3 轻量弹层

- 删除确认弹窗
- 筛选面板
- 依赖说明弹层
- 操作结果 Snackbar

## 12.2 导航关系

推荐跳转关系如下：

```text
我的
-> 属性管理
   -> 属性详情
      -> 属性编辑
      -> 规则绑定页
   -> 规则详情
      -> 规则定义编辑页
   -> 模板详情
      -> 从模板创建属性
      -> 从模板创建规则
新增页 / 编辑页
-> 去属性管理
```

固定原则如下：

- 列表页负责“发现对象”
- 详情页负责“理解对象”
- 编辑页负责“修改对象”
- 绑定页负责“组装规则实例”
- 创建页负责“生成对象”

## 13. UI 与数据结构落地建议

## 13.1 UI 结构分层

属性管理页建议拆成：

1. Route / Screen 层
2. Header 层
3. Attribute / Rule / Template List Pane 层
4. Card 层
5. Detail / Editor / Binding 层
6. Dialog / Sheet 层

推荐组件划分如下：

```text
AttributeManagementRoute
-> AttributeManagementScreen
   -> AttributeManagementHeader
   -> AttributeListPane
   -> RuleListPane
   -> TemplateListPane
   -> AttributeCard
   -> RuleCard
   -> TemplateCard
   -> EmptyStateCard
   -> DeleteConfirmDialog
```

## 13.2 顶层 UI State 建议

属性管理页推荐采用以下结构：

```kotlin
data class AttributeManagementUiState(
```

## 14. 第一阶段落地范围

第一阶段建议完成：

1. “我的”页面增加 `属性管理` 入口
2. 属性管理页顶部三视图切换：
   - 属性
   - 规则
   - 模板
3. 属性视图基础列表
4. 规则视图基础列表
5. 模板视图基础列表
6. 搜索属性、规则、模板
7. 属性视图筛选
8. 规则视图筛选
9. 模板视图筛选
10. 从属性模板创建属性
11. 从规则模板创建规则
12. 编辑自定义属性
13. 编辑自定义规则
14. 删除自定义属性
15. 删除自定义规则
16. 从属性出发进入规则绑定页
17. 展示属性和规则的使用/绑定统计

第一阶段暂不做：

- 用户自定义模板治理
- 批量迁移属性值
- 规则调试面板
- 批量规则治理

## 15. 最终固定方案

当前可固定的属性管理页方案如下：

1. 属性管理放在“我的”页面中，作为全局基础治理能力。
2. 属性管理页第一阶段固定为三个视图：`属性视图`、`规则视图`、`模板视图`。
3. 属性视图治理属性定义，规则视图治理规则定义，模板视图治理属性模板与规则模板。
4. 属性详情页与规则详情页负责解释对象，编辑页负责修改对象，规则绑定页负责组装规则实例。
5. `新建规则` 与 `添加规则` 是两条不同流程，前者定义规则母版，后者为当前属性创建规则绑定实例。
6. 新增页和编辑页中的轻量创建，不替代属性管理页的完整治理能力。
7. 表单层的规则依赖自动补齐逻辑，需要以规则绑定实例为基础，并在属性管理页中有可见解释。

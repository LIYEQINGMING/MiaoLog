# 当前内置物品属性清单

## 目的
本文档用于说明项目当前代码中已经内置支持的“物品属性”有哪些，作为后续：

- 新增页 UI 设计
- 模板系统设计
- 数据库字段治理
- 自定义属性与系统属性边界划分

的参考依据。

本文档以当前代码实现为准，但在产品语义上明确以“物品/资产管理”为前提，不再把旧库存命名视为产品设计依据。

---

## 1. 说明范围

这里的“内置物品属性”包含四类：

1. 当前新增/编辑流程中可直接使用的系统字段
2. 已有数据库实体承接的标准字段
3. UI/交互过程中使用的辅助字段
4. 旧架构遗留、仍在代码中兼容处理的技术字段

不包含：

- 高级自定义属性 `CustomAttributeDefinitionEntity`
- 用户自行创建的标签值、分类值、子分类值
- 未来规划但当前尚未真正打通的状态定义体系

需要特别说明：

- 当前系统不是库存管理系统
- 文档中的 `InventoryDetailEntity`、`库存` 等表述，仅表示历史技术实现
- 产品上讨论的是“物品属性”，不是“库存属性”

---

## 2. 当前正式内置的系统属性

以下属性已经在当前代码中被正式识别，并且至少满足以下之一：

- 有字段定义或默认属性配置
- 在新增/编辑页面中被读取或写入
- 能落到 `UnifiedItemEntity`、`InventoryDetailEntity`、`WarrantyEntity` 等实体

### 2.1 基础信息

| 属性名 | 类型/表现 | 说明 |
| :--- | :--- | :--- |
| `名称` | 文本 | 必填，物品主标题 |
| `数量` | 数值 | 支持数量单位 |
| `数量_unit` | 单位 | 如 个、件、包、盒、瓶、袋、箱 |
| `位置` | 文本/结构化位置结果 | 用于存放位置展示，通常由三级位置字段拼接生成 |
| `备注` | 多行文本 | 物品说明、来源、补充信息 |
| `分类` | 单选/可自定义 | 当前内置候选值：食品、药品、日用品、电子产品、衣物、文具、其他 |
| `子分类` | 单选/可自定义 | 历史兼容字段，长期不再作为设计中心字段 |
| `标签` | 多选标签 | 标签本身可扩展，字段本身属于内置字段 |
| `品牌` | 文本 | 品牌名 |
| `规格` | 文本 | 规格说明 |

### 2.2 数值与评价

| 属性名 | 类型/表现 | 说明 |
| :--- | :--- | :--- |
| `容量` | 数值 | 可用于容量、重量、规格数值 |
| `容量_unit` | 单位 | 当前内置候选值：毫升、升、克、千克、公斤、磅、盎司 |
| `评分` | 数值/星级 | 0 到 5 的评分 |
| `季节` | 多选标签 | 当前内置候选值：春、夏、秋、冬、全年 |
| `购入价格` | 数值 | 历史技术字段名为 `单价`，产品展示统一为 `购入价格` |
| `购入价格_unit` | 单位/币种 | 历史技术字段名为 `单价_unit`，产品展示应统一到价格单位或币种语义 |
| `总价` | 数值 | 总价格 |
| `总价_unit` | 单位/币种 | 与总价配套 |
| `币种` | 文本/枚举 | 新新增页已使用，当前主要写入 `UnifiedItemEntity.currencyCode` |

### 2.3 日期与期限

| 属性名 | 类型/表现 | 说明 |
| :--- | :--- | :--- |
| `添加日期` | 日期 | 默认当前日期 |
| `购买日期` | 日期 | 购买发生时间 |
| `生产日期` | 日期 | 生产日期 |
| `保质期` | 期限 | 支持数值 + 单位 |
| `保质期_unit` | 单位 | 年、月、日 |
| `保质过期时间` | 日期 | 明确的过期日期 |
| `保修期` | 期限 | 支持数值 + 单位 |
| `保修期_unit` | 单位 | 年、月、日 |
| `保修到期时间` | 日期 | 明确的保修到期时间 |

### 2.4 购买与识别

| 属性名 | 类型/表现 | 说明 |
| :--- | :--- | :--- |
| `购买渠道` | 单选/可自定义 | 当前内置候选值：淘宝、天猫、拼多多、京东、美团、其他网购、线下店 |
| `商家名称` | 文本 | 店铺或卖家名称 |
| `序列号` | 文本 | 设备、收藏品等识别编号 |
| `开封状态` | 单选 | 当前内置值：已开封、未开封 |

### 2.5 地点与位置扩展

| 属性名 | 类型/表现 | 说明 |
| :--- | :--- | :--- |
| `地点` | 文本 | 地址或地图地点描述 |
| `地点_纬度` | 数值 | GPS 纬度，辅助字段 |
| `地点_经度` | 数值 | GPS 经度，辅助字段 |
| `位置_area` | 文本 | 结构化位置的区域 |
| `位置_container` | 文本 | 结构化位置的容器 |
| `位置_sublocation` | 文本 | 结构化位置的具体层级位置 |

### 2.6 补充属性扩展与属性动作相关字段

这一组内容当前仍存在于代码和实体结构中，但在新的页面设计中需要区分成两层：

1. 作为物品补充属性本身存在的字段
2. 作为属性动作配置或技术承接字段存在的字段

| 属性名 | 类型/表现 | 说明 |
| :--- | :--- | :--- |
| `不计入总价值` | 布尔 | 当前技术上仍是独立字段，后续设计上应收口为价格型属性的动作配置 |
| `不计入总数量` | 布尔 | 当前技术上仍是独立字段，后续需结合数量类属性语义进一步收口 |
| `订阅制` | 布尔 | 当前仍可视为补充属性，不再单独视为页面功能区字段 |
| `自动续费` | 布尔 | 当前仍可视为补充属性，不再单独视为页面功能区字段 |
| `扣费周期` | 枚举 | 当前仍可视为补充属性，不再单独视为页面功能区字段 |
| `模板ID` | Long | 当前录入时选择的模板 ID，对应 `templateId` |

## 5. 当前“字段”和“能力”的边界

为避免混淆，需要明确以下内容不是“内置系统属性字段”，而是另一层能力：

### 5.1 高级自定义属性

这部分不属于固定内置物品属性，而是模板或用户定义后动态挂载的属性。

当前支持的自定义属性类型：

- `TEXT`
- `NUMBER`
- `PRICE`
- `DATE`
- `BOOLEAN`

它们通过：

- `CustomAttributeDefinitionEntity`
- `ItemCustomAttributeEntity`

实现，而不是写死在系统字段列表中。

### 5.2 属性动作配置

为了避免把“属性本体”和“属性动作”继续混为同级字段，需要明确：

- `PRICE`、`DATE`、`NUMBER`、`BOOLEAN`、`TEXT` 这些是属性类型
- 某些类型未来可以携带自己的动作配置
- 动作配置应被理解为“属性块的一部分”，而不是单独页面分区

例如：

- `购入价格` 是属性
- `不计入总价`、`不计入日均价值` 是这个属性未来可支持的动作

当前阶段：

- 系统仅允许创建属性，并为属性配置它本来支持的动作
- 不开放用户自定义动作种类

### 5.3 标签值、分类值、子分类值

这些字段本身是内置字段，但字段里的可选值并不是完全固定：

- `分类` 支持用户扩展
- `子分类` 依赖分类变化且支持自定义，但产品设计上已不再作为长期中心字段
- `标签` 支持用户扩展

因此应区分：

- “字段是内置的”
- “字段的取值是可扩展的”

## 6. 当前新增/修改页默认重点展示的属性

从当前设计文档看，默认优先录入的属性主要是：

- `名称`
- `分类`
- `数量`
- `标签`
- `品牌`
- `规格`
- `状态`

按需补充的典型属性包括：

- `购入价格`
- `总价`
- `购买日期`
- `购买渠道`
- `商家名称`
- `备注`
- `位置`
- `地点`
- `序列号`
- `保质期`
- `保修期`
- 各类高级自定义属性

页面结构上固定为：

- 图片区
- 基础信息区
- 补充信息区

不再继续按“价值与来源”“位置与识别”“生命周期”“统计控制”等旧专题区分区。

## 7. 当前结论

如果只看“当前系统内置、由代码明确识别的物品属性”，可以概括为以下几层：

1. 核心识别属性：`名称`、`分类`、`品牌`、`规格`、`备注`
2. 数值属性：`数量`、`容量`、`评分`、`购入价格`、`总价`
3. 时间属性：`添加日期`、`购买日期`、`生产日期`、`保质期`、`保质过期时间`、`保修期`、`保修到期时间`
4. 来源与识别属性：`购买渠道`、`商家名称`、`序列号`、`标签`、`季节`
5. 位置属性：`位置`、`地点` 及其结构化辅助字段
6. 补充属性与动作扩展项：`币种`、`不计入总价值`、`不计入总数量`、`订阅制`、`自动续费`、`扣费周期`、`模板ID`
7. 遗留兼容属性：`库存预警值`、`高周转`、`加入心愿单`、`开封时间`

---

## 8. 后续建议

为了让后续设计和开发更稳定，建议下一步做一轮“系统属性收口”：

1. 明确哪些字段继续保留为系统内置属性
2. 明确哪些字段应转为“属性块内动作配置”
3. 明确哪些旧库存语义字段应停用或迁移
4. 形成一份正式的“系统属性白名单”，供新增页、编辑页、模板页统一使用

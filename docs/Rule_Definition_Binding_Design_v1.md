# 规则定义与绑定设计稿 v1

## 1. 文档定位

本文档基于当前已经确认的物品-属性-规则关系，进一步把“规则定义”和“规则绑定实例”收口为可指导产品设计、数据建模与实现的专项设计稿。

本文档重点回答以下问题：

- 规则定义现在到底定义什么
- 规则绑定实例现在到底绑定什么
- 可视化公式画布如何回到正式模型
- 用户开关控制、周期调度、规则实例绑定三者如何配合

---

## 2. 设计目标

当前阶段，规则系统的目标不是构建通用低代码平台，而是稳定解决以下问题：

1. 让用户可以定义一条可执行规则。
2. 让用户可以用可视化画布描述公式结构。
3. 让用户可以在物品页把属性绑定到规则槽位。
4. 让系统可以根据规则实例自动补齐依赖属性并执行规则。
5. 让周期类规则可以通过调度事件驱动执行。

因此当前设计必须满足：

- 简单规则仍然足够轻
- 复杂规则有统一模型
- 规则定义、规则绑定、规则运行共享同一套语义
- 编辑器体验直观可理解

---

## 3. 核心结论

当前阶段正式固定以下核心结论：

1. 规则最本质上是“槽位化公式结构 + 调度能力 + 启用控制”。
2. 规则编辑页的主视图是“可视化公式画布”，不是变量表单。
3. 槽位仍然是正式持久化模型的一部分，不是临时 UI 结构。
4. 规则绑定实例不再从属性定义侧持久化，而是挂在物品上。
5. `用户开关控制` 不是触发方式，而是是否暴露物品页启停开关。
6. `ON_VALUE_CHANGED + ON_SAVE` 是默认基础触发器，不需要在编辑页单独配置。
7. 周期规则通过 `SCHEDULED` 触发，并由调度规则生成事件交给运行器执行。
8. “规则类型”不再是编辑页的核心配置项，前端第一阶段统一按自定义规则处理。

---

## 4. 顶层模型

当前阶段规则模型正式收敛为五个对象：

1. 规则定义
2. 槽位定义
3. 公式画布结构
4. 规则绑定实例
5. 调度规则

其中：

- 规则定义负责描述“这条规则母版长什么样”
- 槽位定义负责描述“这条规则有哪些输入输出位置”
- 公式画布结构负责描述“这些槽位如何参与计算”
- 规则绑定实例负责描述“在某个物品上，槽位实际绑定到了什么”
- 调度规则负责描述“何时产生执行事件”

---

## 5. 规则定义

### 5.1 规则定义是什么

规则定义回答的是：

- 这条规则叫什么
- 它的公式结构是什么
- 它有哪些输入槽位和输出槽位
- 这些槽位的方向、值来源、值类型是什么
- 它是否允许用户在物品页控制启停
- 它是否需要周期调度

规则定义本身不直接绑定某个具体物品属性。

### 5.2 规则定义的核心字段

第一阶段建议规则定义严格收敛为以下字段：

1. 规则名
2. 规则说明
3. 槽位定义列表
4. 公式结构定义
5. 输出策略
6. 启用控制配置
7. 触发方式
8. 调度配置
9. 描述

### 5.3 关于规则类型的正式结论

当前正式结论：

- `RuleComputationType` 暂时保留在数据层
- 但不再作为规则编辑页的主配置项
- 前端第一阶段统一按 `CUSTOM` 处理

也就是说：

- “规则类型”不再驱动规则结构
- 它最多只承担模板分组、列表归类、历史兼容等职责

---

## 6. 槽位定义

### 6.1 槽位定义是什么

槽位定义是规则模型的核心。

槽位定义回答的是：

- 这条规则里有哪些变量位置
- 每个位置是输入还是输出
- 每个位置是什么值类型
- 每个位置的值来自哪里
- 某个位置在规则定义阶段是否已经固定值

### 6.2 槽位定义的核心字段

第一阶段建议槽位定义包含以下字段：

1. 槽位 key
2. 槽位名称
3. 槽位方向
4. 槽位值类型
5. 槽位值来源
6. 是否必填
7. 是否允许快捷创建属性
8. 描述

### 6.3 槽位方向

第一阶段固定为：

1. 输入槽位
2. 输出槽位

### 6.4 槽位值来源

当前正式支持以下几类：

1. 系统级变量
2. 外部输入
3. 固定值

含义如下：

- `系统级变量`
  - 值来自整个 App 的系统变量
- `外部输入`
  - 规则定义阶段没有具体值
  - 后续在物品规则实例里由属性或物品级变量提供
- `固定值`
  - 规则定义阶段就写死值

### 6.5 槽位值类型

建议支持：

- 文本
- 数值
- 日期
- 布尔
- 选择
- 周期单位

---

## 7. 可视化公式画布

### 7.1 画布的正式角色

画布是规则编辑体验的主入口。

用户通过画布来：

- 放置槽位
- 放置计算符
- 放置函数块
- 放置常量块
- 形成公式结构

### 7.2 用户可拖拽对象

第一阶段可拖拽对象固定为：

1. 空槽位
2. 计算符
3. 函数块
4. 常量块

### 7.3 空槽位的配置弹窗

空槽位放下后，必须弹出配置框，至少配置：

- 变量名称
- 输入 / 输出方向
- 值来源
  - 系统级变量
  - 外部输入
  - 固定值
- 值类型

### 7.4 第一阶段公式连接方式

第一阶段建议采用：

- 从左到右解析的公式流

原因是：

- 心智简单
- 便于实现
- 已经足够覆盖目前的计算型规则

后续再扩展：

- 连线式连接
- 分支式逻辑
- 多输出复杂流

### 7.5 画布状态提示

画布节点必须能提示：

- 当前是输入还是输出
- 当前值类型
- 当前值来源
- 当前是否未完成配置
- 当前是否类型不兼容
- 当前是否被调度规则引用

固定建议：

- 输入 / 输出用颜色区分
- 值来源用图标或标签区分
- 未完成配置用红边框或警示角标区分

---

## 8. 公式画布与正式模型的映射

### 8.1 正式结论

画布不是新的运行时主模型。

保存后仍然回到：

- `RuleSlotDefinition`
- `RuleExpressionDefinition`
- `RuleOutputStrategyDefinition`

### 8.2 映射规则

保存时统一做以下映射：

- 画布中的槽位节点 -> `RuleSlotDefinition`
- 画布中的结构顺序 / 连接关系 -> `RuleExpressionDefinition`
- 输出节点定义 -> `RuleOutputStrategyDefinition`

因此：

- 画布负责编辑体验
- 数据模型继续负责正式落库与运行时消费

---

## 9. 触发方式与启用控制

### 9.1 触发方式

当前正式支持：

- `ON_VALUE_CHANGED`
- `ON_SAVE`
- `SCHEDULED`

固定解释：

- 普通计算型规则默认至少具备 `ON_VALUE_CHANGED + ON_SAVE`
- 这两个默认触发器不在编辑页显式展示
- 只有需要周期触发的规则，才额外声明 `SCHEDULED`

### 9.2 启用控制

规则定义需要单独声明启用控制配置：

- `activationMode`
  - `ALWAYS_ON`
  - `USER_TOGGLE`
- `toggleUiConfig`
  - `labelWhenEnabled`
  - `labelWhenDisabled`
  - `anchorSlotKey`
  - `defaultEnabled`

固定原则：

- `activationMode` 只表达“是否向用户暴露启停能力”
- 它不再表达规则的运行方式

---

## 10. 周期调度

### 10.1 周期调度的正式解释

当规则包含 `SCHEDULED` 时：

- 系统需要为其生成调度事件
- 这些事件后续由运行器消费执行

因此：

- 周期调度不是一个普通文本字段
- 它本质上是一份日历规则

### 10.2 调度来源

周期调度固定支持两种来源：

1. 手动配置日历规则
2. 来自槽位

### 10.3 手动配置日历规则

手动配置时，建议支持：

- 开始时间
- 是否包含时分
- 重复频率
  - 每日
  - 每周
  - 每月
  - 每年
  - 自定义
- 重复间隔
- 结束条件
  - 永不结束
  - 截止日期
  - 发生 N 次
- 时区

### 10.4 来自槽位

当调度由槽位驱动时，槽位可以承担：

- 开始时间
- 周期单位
- 周期间隔
- 结束条件
- 时区

### 10.5 调度事件配置

调度配置还需要包括：

- 事件标题模板
- 去重策略

---

## 11. 规则绑定实例

### 11.1 规则绑定实例是什么

规则绑定实例回答的是：

- 在某个物品里，这条规则的每个槽位实际绑定到了什么

绑定实例是“规则母版在物品中的一次具体落地”。

### 11.2 绑定实例的核心字段

第一阶段建议规则绑定实例至少包含：

1. 绑定实例 id
2. 规则定义 id
3. 所属物品 id
4. 槽位绑定表
5. 当前是否启用
6. 开关展示锚点
7. 是否完整
8. 运行时状态

### 11.3 绑定类型

规则实例中的槽位绑定主要包括：

- 属性输入绑定
- 属性输出绑定
- 系统变量绑定
- 固定值绑定

### 11.4 运行时状态

对于带调度能力的规则实例，建议补充最小运行时状态：

- `lastExecutedAt`
- `nextRunAt`
- `lastGeneratedEventAt`
- `lastExecutionFingerprint`

---

## 12. 从物品页出发的绑定流程

### 12.1 正式入口

规则绑定的正式入口现在收口到：

- 物品新增页 / 编辑页的规则 Tab

而不是属性定义页。

### 12.2 绑定流程

推荐流程如下：

1. 用户在物品页选择一条规则
2. 规则卡片展示公式槽位
3. 用户点击槽位
4. 弹出属性 / 系统变量选择器
5. 为槽位绑定具体来源
6. 规则卡片实时提示是否缺少必填绑定

### 12.3 绑定完整性的判定

一条规则实例只有在以下条件全部满足后，才算完整：

1. 所有必填输入槽位都已绑定
2. 所有必填输出槽位都已绑定
3. 所有绑定都通过类型检查
4. 调度规则所依赖的槽位都已补齐

未完成绑定的规则实例：

- 允许以草稿状态存在
- 不进入运行器执行
- 在物品页以浅红边框提示用户继续补齐

---

## 13. 与物品编辑页的联动

### 13.1 属性页与规则页分工

物品页中：

- 属性页负责展示与编辑属性
- 规则页负责展示与绑定规则

### 13.2 用户开关控制的表现

当规则定义开启 `USER_TOGGLE` 后：

- 物品页规则 Tab 中可看到规则开关配置结果
- 属性页中会在对应锚点属性下显示开关

### 13.3 周期规则的表现

当规则带有 `SCHEDULED`：

- 物品页规则 Tab 应可看见其调度摘要
- 若调度相关槽位未补齐，也应提示用户

---

## 14. 第一阶段固定边界

### 14.1 当前正式支持

- 可视化公式画布
- 槽位化输入输出定义
- 用户开关控制
- 周期调度规则
- 从物品页出发的规则绑定
- 槽位点击后绑定属性 / 系统变量
- 缺失槽位提示
- 规则实例运行时状态最小持久化

### 14.2 当前暂不优先支持

- 完整低代码流程编排
- 自由连线无限画布
- 完整多分支执行图
- 规则调试沙箱
- 规则类型驱动编辑体验

---

## 15. 当前设计稿的最终结论

当前可以正式固定以下结论：

1. 规则定义的核心已经从“规则类型 + 表达式文本”转向“槽位 + 画布 + 调度”。
2. 规则编辑页的主视图是可视化公式画布，不再是变量管理大表单。
3. 槽位必须显式声明方向、值类型、值来源，并继续作为正式模型落库。
4. `用户开关控制` 是启用配置，不是运行方式。
5. `SCHEDULED` 代表由调度规则生成事件，再交给运行器执行。
6. 周期调度必须支持手动配置日历规则，以及由槽位驱动调度规则两种模式。
7. 规则绑定的真正对象仍然是“规则实例”，不是简单规则名列表。
8. 物品页是规则-属性绑定的正式入口，属性定义页不再持久化真实规则实例。

# 首页设计文档

## 1. 文档目的

本文档用于固定“首页”的整体设计方案，作为后续以下模块的统一依据：

- 首页的信息架构与页面定位
- 资产总览卡、快捷入口、物品流的组织方式
- 首页与搜索、筛选、统计、购物清单之间的关系
- 现有 `HomeDashboard` 与后续首页重构的统一方向

本文档聚焦的是：

- `首页为什么存在`
- `首页应该优先展示什么`
- `首页如何兼顾总览、效率和发现`

---

## 2. 首页的页面定位

### 2.1 核心定位

首页不是单纯的物品列表页，也不是完整的统计页。

首页应定义为：

- `每日进入应用后的第一屏`
- `个人物品世界的总览页`
- `高频操作和高优先事项的收口页`

也就是说，首页同时承担三类职责：

1. 告诉用户“我现在拥有什么”
2. 告诉用户“我现在应该关注什么”
3. 让用户快速进入“我接下来要做什么”

### 2.2 首页不应该做什么

首页不应该承担：

- 全量复杂统计分析
- 超长设置入口聚合
- 完整物品管理后台
- 过重的编辑型表单流程

因此固定一条原则：

- `首页负责总览、提醒和快速进入，不负责完整治理`

---

## 3. 当前现状与问题

结合当前实现，首页已经具备以下基础能力：

- 顶部标题
- 资产总览卡
- 物品数量 / 分类数量 / 标签数量摘要
- 物品流展示
- 分类筛选
- 排序
- 瀑布流 / 列表切换

这说明首页已经形成了基础雏形，但仍然存在几个结构性问题：

1. 资产总览和物品流之间缺少“高优先事项”层。
2. 首页是“有列表、有总览”，但还不像一个真正的首页。
3. 当前更像“带总览头部的物品清单页”，而不是“有节奏的信息入口页”。
4. 首页配置项已经存在数据基础，但在页面中还没有形成清晰的卡片入口层。
5. 搜索、推荐、提醒、购物等能力在首页中的分工还没有被固定下来。

因此，这份文档需要把首页从：

- `列表页 + 总览卡`

升级为：

- `总览页 + 提醒页 + 快速进入页 + 发现页`

---

## 4. 首页整体结构

### 4.1 推荐分层

首页建议固定为五层结构：

1. `首页头部`
2. `资产总览层`
3. `高优先事项层`
4. `快捷入口层`
5. `物品流层`

### 4.2 推荐页面结构

```text
首页
├── 顶部头部
│   ├── 页面标题
│   ├── 搜索入口
│   └── 可选的问候语/时间语义
├── 资产总览
│   ├── 总价值
│   ├── 日均价值
│   ├── 物品数
│   ├── 分类数
│   └── 标签数
├── 高优先事项
│   ├── 即将到期
│   ├── 已过期
│   ├── 低数量提醒
│   └── 购物清单
├── 快捷入口
│   ├── 添加物品
│   ├── 日历
│   ├── 搜索/筛选
│   └── 统计
└── 物品流
    ├── 智能推荐
    ├── 分类筛选
    ├── 排序
    ├── 视图切换
    └── 瀑布流/列表
```

这个结构中最关键的调整是：

- 把“高优先事项层”和“快捷入口层”补上

这样首页才真正具备“入口页”的属性。

---

## 5. 首页头部设计

### 5.1 标题策略

首页标题仍然可以使用：

- `首页`

但不建议过度放大标题字号。

更推荐：

- 中等标题
- 简洁稳重
- 不抢占上方视觉空间

### 5.2 搜索入口

首页应有明确搜索入口。

原因是：

1. 搜索是高频能力。
2. 用户进入首页后，经常是带着明确目标来的。
3. 搜索不应该只存在于专门的搜索页中。

首页搜索的职责应是：

- 快速跳转全局搜索
- 或在首页内直接进入搜索模式

### 5.3 问候语是否需要

首页可以有轻量问候语，但不建议做成强运营化内容。

例如：

- `今天也来整理一下你的物品`
- `你有 3 个项目值得关注`

但这类内容应服从功能，不应喧宾夺主。

---

## 6. 资产总览层

### 6.1 资产总览的定位

资产总览是首页最核心的摘要模块，用来回答：

- `我现在一共管理了多少东西`
- `这些东西整体价值如何`

### 6.2 展示指标

首页第一版建议固定展示：

- `总价值`
- `日均价值`
- `物品数量`
- `分类数量`
- `标签数量`

这些指标的特点是：

- 足够轻
- 易理解
- 与首页“总览页”定位一致

### 6.3 展示方式

资产总览建议采用：

- 一个统一的大卡片
- 左侧并列展示核心金额指标
- 下方展示轻量摘要标签

金额指标建议固定为：

- `总价值`
- `日均价值`

并遵循以下规则：

- 两个指标放在同一视觉层级
- 左对齐展示
- 保持相同字体权重
- 用较大间距拉开，但不要一左一右顶满整行

### 6.4 视觉原则

资产总览作为首页主结构模块，不建议做成过于透明或过度炫技的玻璃悬浮块。

更推荐：

- 干净统一的容器背景
- 稳定、易读的数据层级
- 少量高光或轻质感细节即可

也就是说：

- `资产总览首先是信息容器，其次才是装饰卡片`

---

## 7. 高优先事项层

### 7.1 为什么必须补这一层

如果首页只有“总览”和“列表”，用户虽然能看到资产，但不知道：

- 今天最该处理什么

因此首页需要一个“高优先事项层”，统一收口用户现在最需要关注的内容。

### 7.2 第一阶段建议入口

第一阶段建议固定以下四个入口：

- `即将到期`
- `已过期`
- `低数量提醒`
- `购物清单`

这四项已有较明确的数据基础，也和当前设置页中的首页功能配置方向一致。

### 7.3 展示方式

推荐使用轻量状态卡或胶囊卡：

- 显示标题
- 显示数量
- 点击进入对应列表

例如：

```text
即将到期  3
已过期    1
低数量提醒 2
购物清单  5
```

### 7.4 配置能力

这些入口应支持用户在设置中开关显示。

固定规则：

- 首页展示哪些高优先事项，由首页配置决定
- 首页只显示被启用的入口
- 未启用的入口不占空间

---

## 8. 快捷入口层

### 8.1 快捷入口的职责

快捷入口不是为了堆功能，而是为了收口高频跳转。

建议优先承载：

- 高频
- 明确
- 可预期

的功能。

### 8.2 第一阶段推荐入口

建议优先考虑：

- `添加物品`
- `日历`
- `搜索`
- `统计`

如果首页已经有明显搜索入口，则快捷入口中的“搜索”可被替换为：

- `模板创建`
- `购物清单`

### 8.3 展示方式

快捷入口建议采用：

- 小卡片
- 单行可横滑
- 或 2x2 轻量宫格

但第一版不建议做成很重的九宫格首页。

原因是：

- 首页主角仍应是总览与物品流
- 快捷入口只是辅助加速层

---

## 9. 物品流层

### 9.1 物品流的定位

首页底部的大列表不应再被理解为“全部物品列表”，而应理解为：

- `首页物品流`

它的特点是：

- 可推荐
- 可筛选
- 可排序
- 可切换视图

### 9.2 智能推荐模式

当前已有“智能推荐”排序语义，这一方向应保留。

首页的默认流建议优先采用：

- 智能推荐

它与“全部物品页”形成区分：

- 首页看“值得先看什么”
- 全部物品页看“完整数据集合”

### 9.3 排序模式

建议保留当前已有排序：

- 智能推荐
- 最新添加
- 最早添加
- 价格最高
- 价格最低
- 名称

但要固定一条原则：

- 排序是对首页物品流的排序，不是对全库的复杂治理操作

### 9.4 筛选模式

首页第一版建议保留轻量分类筛选。

也就是说：

- 首页做单一轻筛选
- 复杂多维筛选交给独立搜索/筛选页

这样可以保持首页轻盈，不变成复杂筛选后台。

### 9.5 视图切换

当前已有：

- 瀑布流
- 列表

这一能力建议保留。

适用建议：

- 图片强、偏展示型的内容适合瀑布流
- 信息密度高、偏检索型内容适合列表

### 9.6 与“全部物品页”的区别

首页的物品流不应完全等同于“所有物品”。

建议固定差异：

- 首页：推荐优先、轻筛选、快速浏览
- 全部物品页：完整集合、重筛选、深操作

---

## 10. 首页与其他页面的关系

### 10.1 与“搜索”页的关系

首页负责：

- 提供搜索入口
- 提供轻量筛选

搜索页负责：

- 全局检索
- 多维过滤
- 精准定位

### 10.2 与“统计”页的关系

首页负责：

- 给出少量高价值摘要数据

统计页负责：

- 完整分析
- 图表
- 趋势
- 交叉筛选

### 10.3 与“日历”页的关系

首页高优先事项中可以出现：

- 即将到期
- 已过期

但详细的时间维度浏览，仍然应该交给：

- 日历页

### 10.4 与“购物清单”页的关系

首页可以展示购物清单摘要入口，但不应在首页承载完整购物流程。

首页职责是：

- 告诉用户“还有多少待买项目”

购物清单页职责是：

- 管理购物内容本体

---

## 11. 与现有实现的兼容策略

### 11.1 当前可直接保留的部分

现有首页中可以直接沿用的方向包括：

- 首页标题
- 资产总览数据源
- 物品数量/分类数量/标签数量摘要
- 分类筛选
- 排序菜单
- 列表/瀑布流切换
- 物品卡片展示

### 11.2 当前需要补齐的部分

建议补齐：

- 搜索入口
- 高优先事项层
- 快捷入口层
- 首页物品流与“全部物品”之间的边界
- 首页配置项在 UI 中的真实落位

### 11.3 不建议第一阶段做的内容

不建议首页第一阶段就加入：

- 复杂多图表分析
- 大量运营式推荐模块
- 复杂社交化信息流
- 过长的多分区瀑布流内容

---

## 12. 第一阶段落地范围

第一阶段建议完成：

1. 首页头部
2. 资产总览卡
3. 高优先事项层
4. 快捷入口层
5. 智能推荐物品流
6. 分类轻筛选
7. 排序与视图切换

第一阶段暂不做：

- 超复杂推荐算法可视化说明
- 个性化首页自由编排
- 重运营内容流
- 大量图表卡片直接塞进首页

---

## 13. UI 结构稿

### 13.1 设计风格方向

首页 UI 结构稿建议结合当前比较流行的移动端设计趋势，但要做本产品自己的收敛，而不是直接照搬。

推荐采用的方向是：

- `大背景轻氛围 + 核心模块实心容器 + 局部轻玻璃点缀`

也就是说：

- 页面背景可以有轻微渐变和氛围光感
- 主要结构卡片应保持清晰、稳定、可读
- 搜索框、悬浮入口、状态胶囊可以使用更轻的玻璃化或半透明效果
- 资产总览这类主结构模块，优先使用统一容器，不做过度透明

这类组合方式更接近当前主流产品的共识：

1. 背景可以有情绪
2. 主信息层必须稳定
3. 点缀层可以更轻盈

### 13.2 页面骨架

首页建议采用：

- `单列纵向滚动`
- `顶部沉浸式头部`
- `内容分区卡片化`
- `关键操作固定在首屏内`

骨架如下：

```text
┌─────────────────────────────┐
│ 状态栏区域                  │
│ 首页         搜索   消息/设置 │
│ 今天也来整理一下你的物品      │
├─────────────────────────────┤
│ 资产总览卡                   │
│ 总价值      日均价值         │
│ 物品数  分类数  标签数       │
├─────────────────────────────┤
│ 高优先事项                   │
│ 即将到期  已过期  低数量  购物 │
├─────────────────────────────┤
│ 快捷入口                     │
│ 添加物品  日历  搜索  统计    │
├─────────────────────────────┤
│ 物品流头部                   │
│ 推荐流    分类筛选   排序 切换 │
├─────────────────────────────┤
│ 物品卡片 / 瀑布流 / 列表      │
│ ...                         │
└─────────────────────────────┘
```

### 13.3 首屏结构稿

首屏建议控制在：

- 用户进入后无需滚动，就能看到
  - 页面身份
  - 核心资产信息
  - 当前待处理事项
  - 至少 2 个快捷入口

推荐首屏从上到下依次为：

1. 顶部头部
2. 资产总览卡
3. 高优先事项
4. 快捷入口的第一行

也就是说，物品流可以位于首屏底部临界线附近，但不强求完整露出。

### 13.4 顶部头部结构

顶部头部建议采用：

- 左侧标题区
- 右侧操作区

推荐布局：

```text
首页                    [搜索] [更多]
今天也来整理一下你的物品
```

规则如下：

- 标题使用中等标题，不要过大
- 次级文案只保留一行
- 搜索按钮优先级高于其他按钮
- 如有更多按钮，可承接首页设置、消息或入口聚合

如果首页后续引入全局搜索框，也建议采用：

- 独立圆角搜索条

而不是把搜索藏得太深。

### 13.5 资产总览卡结构

资产总览卡建议作为首页最大的单个模块。

推荐结构如下：

```text
┌─────────────────────────────┐
│ 资产总览                     │
│ ￥ 128,560     ￥ 352 / 天    │
│ 总价值         日均价值       │
│                             │
│ 128 物品   18 分类   46 标签  │
└─────────────────────────────┘
```

结构规则：

- 标题放在卡片左上
- `总价值` 与 `日均价值` 放在同一行左侧区域
- 两项数值保持同等权重，不要一大一小拉开层级
- 两项之间用较大间距拉开，但整体仍左对齐
- 底部三个摘要数字建议横向排布

尺寸建议：

- 卡片圆角：`20dp` 到 `24dp`
- 内边距：`20dp`
- 标题与数据组间距：`12dp`
- 两个金额指标间距：`32dp` 到 `40dp`
- 卡片下方摘要项间距：`16dp` 到 `20dp`

### 13.6 高优先事项结构

高优先事项建议采用：

- `2 x 2` 轻量网格

而不是横向滚动跑马灯。

原因是：

- 信息更稳定
- 数量更容易对比
- 更适合高优先级状态展示

推荐结构：

```text
高优先事项
┌──────────┬──────────┐
│ 即将到期 3 │ 已过期 1  │
├──────────┼──────────┤
│ 低数量 2  │ 购物清单 5 │
└──────────┴──────────┘
```

单卡建议包含：

- 图标
- 标题
- 数量
- 状态色点缀

视觉规则：

- 卡片比资产总览更轻
- 可以用浅色背景区分状态
- 不建议全部都用高饱和警示色

### 13.7 快捷入口结构

快捷入口建议采用：

- `四宫格`

这是当前移动端比较稳定也最容易理解的结构。

推荐结构：

```text
快捷入口
┌──────────┬──────────┐
│ 添加物品  │ 日历      │
├──────────┼──────────┤
│ 搜索      │ 统计      │
└──────────┴──────────┘
```

每个入口建议包含：

- 小图标
- 1 行标题

不建议在首页快捷入口里放过多副标题，否则首屏会显得很碎。

视觉规则：

- 快捷入口卡片尺寸比高优先事项再轻一档
- 图标可用强调色做区分
- 背景保持统一，不建议每个入口一套色

### 13.8 物品流头部结构

物品流头部建议采用：

- 左侧标题
- 中间筛选胶囊
- 右侧两个工具按钮

推荐结构：

```text
推荐物品
[全部] [电子产品] [收藏]
排序   视图切换
```

更推荐实际布局为两行：

1. 第一行：标题 + 排序 + 视图切换
2. 第二行：横滑分类筛选胶囊

这样比把所有控件塞一行更清晰。

### 13.9 物品卡片结构

瀑布流模式下，单卡建议采用当前流行的内容卡布局：

- 上方大图
- 中间名称
- 下方两行轻信息

推荐结构：

```text
┌──────────────┐
│ 图片          │
│              │
├──────────────┤
│ Sony WH-1000 │
│ ￥1999       │
│ 电子产品      │
└──────────────┘
```

列表模式下，建议采用：

- 左图右文
- 右侧信息分成标题、价格、附加信息三层

列表卡更适合快速浏览和搜索结果场景。

### 13.10 滚动行为建议

首页滚动时建议采用以下规则：

1. 顶部背景氛围可以随滚动逐渐减弱
2. 搜索按钮和右上操作始终可达
3. 物品流头部可在滚动到列表区域后轻度吸顶
4. 资产总览和高优先事项不建议强吸顶

这样可以兼顾：

- 首页感
- 列表浏览效率

### 13.11 加载、空态和异常

首页 UI 结构稿还应提前固定三种状态：

#### 加载态

建议使用：

- 资产卡骨架屏
- 2 x 2 状态卡骨架
- 物品卡骨架流

#### 空态

当用户还没有物品时，首页建议结构为：

- 仍保留头部
- 资产总览显示 `0`
- 快捷入口保留
- 物品流位置显示空态插画和“去添加物品”

#### 异常态

首页数据加载失败时：

- 顶部和已有缓存优先保留
- 失败区块局部显示重试
- 不建议整页大面积错误中断

### 13.12 组件样式建议

首页 UI 建议使用以下组件语言：

- 圆角：主卡 `20dp` 到 `24dp`
- 小卡 `16dp` 到 `20dp`
- 页面左右边距：`16dp`
- 模块上下间距：`16dp` 到 `20dp`
- 图标容器：圆角小底板或无底板线性图标
- 按钮：优先 pill 或圆角矩形，不建议方形硬边

颜色建议：

- 页面背景可轻渐变
- 主容器用统一表面色
- 强调色只点到关键数据、按钮和状态
- 不建议整页到处用强渐变

## 14. 最终固定方案

当前可固定的首页设计方案如下：

1. 首页定义为总览页、提醒页、快速进入页的组合页。
2. 首页整体结构固定为“头部 + 资产总览 + 高优先事项 + 快捷入口 + 物品流”。
3. 资产总览是首页主摘要模块，核心展示总价值与日均价值。
4. 高优先事项层统一承接即将到期、已过期、低数量提醒、购物清单等需要立即关注的内容。
5. 快捷入口层只承载高频跳转，不做复杂功能堆叠。
6. 首页底部采用“首页物品流”，默认优先展示智能推荐，而不是简单等同于全部物品列表。
7. 首页保留轻量分类筛选、排序、列表/瀑布流切换。
8. 复杂搜索交给搜索页，完整分析交给统计页，完整购物流程交给购物清单页。
9. 首页 UI 结构稿采用“轻氛围背景 + 稳定主容器 + 局部轻玻璃点缀”的组合方式。
10. 首屏优先展示头部、资产总览、高优先事项和快捷入口，不强求首屏完整露出物品流。
11. 高优先事项采用 `2 x 2` 轻量网格，快捷入口采用四宫格，物品流采用两行式头部和可切换的瀑布流/列表。

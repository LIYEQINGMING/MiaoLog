# 规则详情页设计文档 v1

## 1. 文档定位

本文档用于定义 V1 阶段的“规则详情页”，统一规则详情在产品层的表达方式。

本文档重点回答：

- 规则详情页应该展示什么，才能让用户真正理解一条规则
- 当前页面里的“运行时映射”该如何升级为 V1 语义
- 详情页如何同时承接规则定义、槽位定义、输出策略和使用范围

本文档主要对应：

- `AttributeManagementRouteState.RuleDetail`
- `RuleDetailPage`

---

## 2. 页面定位

规则详情页负责“解释一条规则”。

它负责：

- 展示规则定义摘要
- 展示输入槽位与输出槽位
- 展示表达式
- 展示输出策略
- 展示被哪些属性使用
- 展示当前可执行操作

它不负责：

- 直接修改规则结构
- 直接绑定某个属性到规则
- 展示某个物品上的实际运行值
- 展示底层执行日志

固定原则：

- `详情页回答这条规则是什么`
- `编辑页回答这条规则怎么改`
- `绑定页回答这条规则怎么被使用`

---

## 3. 当前页面需要修正的核心问题

当前规则详情页里最容易造成割裂的部分是：

- “规则结构”仍偏旧模型
- “运行时映射”表达模糊
- “操作”更像管理动作，不像规则语义

V1 下需要统一改成以下语言：

- 规则定义
- 槽位定义
- 表达式
- 输出策略
- 绑定使用范围

尤其需要固定：

- `系统输入` 不再只是“运行时映射”的子项，而是槽位来源类型的一部分
- `输出目标` 不再只是说明文本，而是输出策略的一部分

---

## 4. 页面结构

规则详情页建议固定为以下结构：

1. 头部摘要
2. 规则定义
3. 槽位定义
4. 表达式与输出策略
5. 绑定与影响范围
6. 操作区

推荐结构：

```text
规则详情
- 头部摘要
- 规则定义
- 输入槽位 / 输出槽位
- 表达式 / 输出策略
- 绑定属性与影响范围
- 编辑 / 删除
```

---

## 5. 头部摘要

头部摘要建议展示：

- 规则图标
- 规则名称
- 来源标签
- 规则类型
- 绑定统计

示意：

```text
周期扣费
系统规则 · 周期规则 · 已绑定 6 个属性
```

---

## 6. 规则定义区

规则定义区回答的是“这条规则整体长什么样”。

建议展示：

- 规则类型
- 触发方式
- 描述
- 来源模板

说明：

- `触发方式` 是规则重新计算的时机
- `来源模板` 有助于用户理解这条规则是系统内置还是从规则模板派生

---

## 7. 槽位定义区

## 7.1 为什么必须单独成块

V1 中，槽位定义是规则模型的中心。

如果详情页不把槽位单独讲清楚，用户仍然会把规则理解成：

- 一串输入角色名称
- 一串依赖属性名
- 一串输出键

这会继续割裂规则定义和规则绑定。

## 7.2 展示方式

建议把槽位拆成两组：

1. 输入槽位
2. 输出槽位

每个槽位至少展示：

- 槽位名称
- 槽位 key
- 槽位值类型
- 槽位来源类型
- 是否必填
- 是否允许快捷创建属性
- 说明

## 7.3 输入槽位示意

```text
price
- 名称：价格
- 类型：数值
- 来源：属性输入
- 必填：是

currentDate
- 名称：当前日期
- 类型：系统日期时间
- 来源：系统输入
- 必填：是
```

## 7.4 输出槽位示意

```text
totalPaid
- 名称：累计总价
- 类型：数值
- 来源：属性输出
- 必填：是
- 允许快捷创建属性
```

---

## 8. 表达式与输出策略区

## 8.1 表达式展示

表达式区需要明确告诉用户：

- 规则到底如何计算

建议展示：

- 原始表达式
- 支持函数提示
- 关键说明

例如：

- `cycleCount(startDate, coalesce(endDate, currentDate), chargeDay, cycleStep, cycleUnit) * price`

## 8.2 输出策略展示

输出策略区需要明确告诉用户：

- 输出落到哪里
- 采用什么更新方式

建议展示：

- 输出形态
  - 只读输出
  - 属性写回
  - 系统变量写回
- 更新方式
  - 覆盖型
  - 累计型

如果第一阶段未开放某种模式，也应清楚显示：

- `模型已预留，当前未开放`

---

## 9. 绑定与影响范围区

## 9.1 绑定统计

详情页必须展示：

- 当前有多少个属性使用该规则
- 这些属性分别是什么

## 9.2 影响范围表达

除了显示“绑定属性”，还建议展示：

- 常见入口属性
- 常见输出属性
- 删除规则时会影响哪些绑定实例

这有助于用户理解：

- 这条规则不是抽象配置，而是正在影响哪些字段

## 9.3 推荐展示语义

```text
绑定属性
- 当前已绑定 6 个属性
- 入口属性：QQ会员价格、网易云会员价格、订阅价格
- 常见输出属性：累计总价
```

---

## 10. 操作区

操作区只负责管理动作，不混入规则语义解释。

建议支持：

- 编辑规则
- 删除规则

其中：

- 系统规则当前阶段只允许查看
- 自定义规则允许编辑和删除

推荐提示文案：

- 系统规则：`系统规则当前阶段仅支持查看。`
- 自定义规则：`自定义规则允许继续编辑规则定义、槽位与输出策略。`

---

## 11. 列表页进入详情后的数据要求

详情页数据不建议完全复用列表项，应使用独立模型。

推荐方向：

```kotlin
data class RuleDetailUiModelV1(
    val id: String,
    val name: String,
    val icon: String,
    val sourceLabel: String,
    val ruleType: String,
    val triggerModes: List<String>,
    val description: String?,
    val slotGroups: List<RuleSlotGroupUiModel>,
    val expression: String?,
    val outputStrategySummary: List<String>,
    val boundAttributes: List<String>,
    val boundAttributeCountText: String,
    val isSystemBuiltIn: Boolean,
    val isEditable: Boolean,
    val isDeletable: Boolean,
)
```

其中 `slotGroups` 建议至少区分：

- 输入槽位组
- 输出槽位组

---

## 12. 状态设计

详情页建议至少支持：

1. 加载中
2. 数据展示
3. 加载失败
4. 删除确认弹窗

加载失败时建议展示：

- 标题：`规则详情加载失败`
- 描述：具体失败原因
- 操作：返回上一页或重试

---

## 13. 第一阶段固定边界

第一阶段建议完成：

1. 规则头部摘要
2. 规则定义展示
3. 输入槽位 / 输出槽位展示
4. 表达式展示
5. 输出策略展示
6. 绑定属性统计
7. 编辑 / 删除操作

第一阶段暂不做：

- 表达式逐步执行结果
- 运行时测试面板
- AST 可视化
- 绑定实例逐条展开调试

---

## 14. 最终结论

当前可固定的规则详情页方案如下：

1. 规则详情页必须围绕 V1 的“规则定义 + 槽位定义 + 表达式 + 输出策略 + 绑定范围”展开。
2. 当前模糊的“运行时映射”应升级为明确的槽位来源与输出策略展示。
3. 详情页要让用户看懂规则是什么，不负责直接修改规则结构。
4. 系统规则只允许查看，自定义规则允许进入编辑和删除流程。

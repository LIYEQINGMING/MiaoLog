# 规则管理页设计文档 v1

## 1. 文档定位

本文档用于落地“属性管理页面中的规则视图”，作为规则相关页面的总入口设计稿。

本文档重点回答：

- 规则管理列表页在 V1 中到底管理什么
- 列表页展示哪些信息，才能和新的规则模型保持一致
- 规则列表、搜索、筛选、删除、跳转详情/编辑应如何设计
- 当前页面与 `Rule_Definition_Binding_Design_v1.md` 如何对齐

本文档主要对应：

- `AttributeManagementTab.RULES`
- `RuleListPane`
- `RuleFilterSection`
- `RuleCard`

---

## 2. 页面定位

规则管理页是“规则治理入口”，不是规则运行页。

它负责：

- 浏览全部规则定义
- 搜索规则
- 按来源、规则类型、绑定情况筛选
- 查看规则被哪些属性使用
- 进入规则详情页
- 创建自定义规则
- 编辑自定义规则
- 删除自定义规则

它不负责：

- 在列表页直接做复杂槽位编辑
- 直接配置某个属性的规则绑定实例
- 在列表页直接运行或调试规则
- 展示完整表达式 AST 或执行日志

固定原则：

- `列表页负责发现规则`
- `详情页负责理解规则`
- `编辑页负责定义规则`
- `绑定页负责组装规则实例`

---

## 3. 核心设计原则

## 3.1 列表对象是“规则定义”

规则管理页中的每一项都代表一条“规则定义”，不是规则绑定实例。

因此列表页展示重点应是：

- 规则结构摘要
- 槽位与输出摘要
- 被多少属性引用
- 是否允许编辑与删除

而不是：

- 某个具体物品上的运行结果
- 某次绑定时填了什么配置值

## 3.2 V1 语义优先于旧模型语义

当前页面虽然已经有基础规则列表，但 V1 下需要重新解释这些信息：

- `输入摘要` 应表达为槽位摘要，不再只是 `inputRoles`
- `输出摘要` 应表达为输出槽位与输出策略摘要
- `依赖摘要` 应来自绑定与槽位约束，不再只是字段名拼接
- `运行时映射` 不应出现在列表页作为核心概念

## 3.3 列表页要能看见“影响范围”

规则管理的核心不是只看规则名，而是看：

- 这条规则目前是否被使用
- 被哪些属性使用
- 删除后会影响多大范围

因此 V1 必须保留：

- 绑定属性数量
- 关联属性名称摘要
- 删除前影响提示

---

## 4. 页面结构

规则管理页建议稳定为以下结构：

1. 页面头部
2. 搜索框
3. 筛选区
4. 规则列表区
5. 主操作入口

推荐结构：

```text
属性管理
- Tab：属性 / 规则 / 模板
- 搜索框
- 规则筛选区
- 规则列表
- 新建规则
```

---

## 5. 页面头部与主操作

## 5.1 标题与位置

规则管理页仍属于 `属性管理` 的二级视图，不单独从“我的”页面再拆一级入口。

## 5.2 主操作

列表页主操作固定为：

- `新建规则`

点击后进入：

- `规则定义编辑页`

第一阶段不建议在这里直接暴露：

- 批量导入规则
- 批量删除规则
- 规则调试台

---

## 6. 搜索与筛选

## 6.1 搜索行为

搜索应支持以下命中维度：

- 规则名称
- 规则类型
- 槽位 key 或槽位名称
- 输出槽位名称
- 描述

不建议继续只按：

- 旧的依赖字段名字符串
- 旧的 outputKeys 字符串

## 6.2 筛选维度

V1 固定三类筛选：

1. 来源筛选
   - 全部来源
   - 系统规则
   - 自定义规则
2. 规则类型筛选
   - 全部规则类型
   - 差值规则
   - 平均值规则
   - 周期规则
   - 累计规则
   - 条件规则
   - 自定义表达式规则
3. 绑定情况筛选
   - 全部绑定
   - 已绑定属性
   - 未绑定属性

## 6.3 顶部统计

筛选区应展示：

- 规则总数
- 系统规则数量
- 自定义规则数量
- 已绑定规则数量

这组统计是列表页判断“治理重点”的快速摘要。

---

## 7. 列表卡片设计

## 7.1 每张卡片建议展示的信息

每个规则卡片建议展示：

- 规则图标
- 规则名称
- 来源标签
- 规则类型标签
- 输入槽位摘要
- 输出槽位摘要
- 依赖与影响摘要
- 绑定属性数量
- 关联属性名称摘要

## 7.2 信息优先级

规则卡片中的信息优先级固定如下：

1. 规则名称
2. 来源与规则类型
3. 输入槽位摘要
4. 输出槽位摘要
5. 影响范围摘要
6. 更多操作

## 7.3 卡片示意

```text
周期扣费      [系统规则] [周期规则]
输入：price / chargeDay / startDate / cycleStep / cycleUnit / currentDate
输出：totalPaid -> 属性输出
影响：已绑定 6 个属性
关联属性：QQ会员价格 / 网易云会员价格 / 订阅价格 等
```

## 7.4 摘要规则

输入摘要：

- 优先展示必填槽位
- 可选槽位放在后面或用“等”收口

输出摘要：

- 需要同时体现输出槽位名与输出目标类型

影响摘要：

- 显示绑定数量
- 有名称时展示前 3 个

---

## 8. 更多操作

每个规则卡片应提供“更多操作”入口，推荐包括：

- 查看规则详情
- 编辑规则
- 删除规则

其中：

- 系统规则只允许查看
- 自定义规则允许编辑和删除

---

## 9. 列表状态

规则管理页建议至少支持以下状态：

1. 首屏加载
2. 首屏空状态
3. 搜索无结果
4. 筛选无结果
5. 正常列表
6. 局部刷新
7. 操作失败

## 9.1 首屏空状态

展示建议：

- 标题：`还没有规则`
- 描述：`可以先新建规则，或从规则模板创建后再集中管理。`
- 主操作：`新建规则`

## 9.2 搜索无结果

展示建议：

- 标题：`没有找到匹配规则`
- 描述：`可以调整关键词，继续搜索规则名称、槽位或输出定义。`

## 9.3 筛选无结果

展示建议：

- 标题：`当前条件下没有规则`
- 描述：`请尝试调整筛选条件。`
- 次操作：`清空筛选`

---

## 10. 删除确认设计

删除规则前必须展示影响提示，不允许无提示直接删除。

删除确认弹窗至少需要说明：

- 规则名称
- 当前绑定属性数量
- 关联属性名称摘要
- 删除后会自动移除这些属性上的绑定实例

推荐提示语义：

- `当前有 3 个属性绑定该规则：QQ会员价格、网易云会员价格、订阅价格。删除后会自动移除这些属性上的规则绑定，是否继续？`

---

## 11. 跳转关系

推荐导航关系如下：

```text
规则管理页
-> 规则详情页
-> 规则定义编辑页
-> 规则模板详情页
```

其中：

- 点击卡片进入 `规则详情页`
- 点击“编辑规则”进入 `规则定义编辑页`
- 点击“新建规则”进入 `规则定义编辑页`

---

## 12. UI 状态建议

推荐延续当前结构，但用 V1 语义解释字段：

```kotlin
data class RuleListPaneState(
    val filters: RuleListFilters = RuleListFilters(),
    val contentState: ListContentState = ListContentState.Loading,
    val items: List<RuleListItemUiModel> = emptyList(),
    val totalCount: Int = 0,
    val systemCount: Int = 0,
    val customCount: Int = 0,
    val boundCount: Int = 0,
    val isRefreshing: Boolean = false,
)

data class RuleListItemUiModel(
    val id: String,
    val name: String,
    val icon: String,
    val ruleTypeLabel: String,
    val inputSummary: String,
    val outputSummary: String,
    val dependencySummary: String,
    val sourceLabel: String,
    val isSystemBuiltIn: Boolean,
    val affectedAttributeCount: Int = 0,
    val affectedAttributeCountText: String = "",
    val affectedAttributeNames: List<String> = emptyList(),
)
```

V1 下建议补充的解释规则：

- `inputSummary` 来自槽位定义摘要
- `outputSummary` 来自输出槽位与输出策略摘要
- `dependencySummary` 来自绑定实例影响语义

---

## 13. 第一阶段固定边界

第一阶段建议完成：

1. 规则列表浏览
2. 搜索规则
3. 来源 / 规则类型 / 绑定情况筛选
4. 绑定属性统计
5. 规则详情跳转
6. 规则创建入口
7. 规则编辑入口
8. 删除前影响提示
9. 删除后自动解绑受影响属性

第一阶段暂不做：

- 规则调试面板
- 批量治理
- 规则版本对比
- 列表页直接编辑槽位

---

## 14. 最终结论

当前可固定的规则管理页方案如下：

1. 规则管理页是规则定义的治理入口，不是规则绑定页。
2. 列表对象是“规则定义”，不是规则绑定实例。
3. 页面必须展示规则结构摘要、输出摘要和绑定影响范围。
4. 搜索与筛选要围绕 V1 的槽位和输出语义设计。
5. 系统规则第一阶段只允许查看，自定义规则允许编辑和删除。
6. 删除规则前必须明确提示受影响属性，并在删除后自动移除绑定实例。

# 物品-属性-规则重构与规则启停设计

## 1. 当前正式关系

### 1.1 物品 - 属性

- 物品是属性的集合。
- 属性定义只负责定义字段本身：
  - 名称
  - 值类型
  - 值来源
  - 交互方式
  - 值属性

### 1.2 物品 - 规则

- 规则是物品内部属性之间的业务关系。
- 规则不再从属于某个属性定义。
- 规则实例直接挂在物品上，由物品决定是否启用、槽位是否绑定完整。

### 1.3 属性 - 规则

- 属性通过规则槽位参与规则。
- 某个属性可以被绑定到规则的输入槽位，为规则提供值。
- 某个属性也可以被绑定到规则的输出槽位，接收规则结果。

---

## 2. 规则定义与规则实例分层

### 2.1 规则定义负责什么

规则定义负责描述：

- 规则名称
- 规则类型
- 输入槽位 / 输出槽位
- 槽位值类型
- 槽位来源类型
- 公式表达式
- 输出策略
- 规则启用方式

### 2.2 规则实例负责什么

规则实例负责描述：

- 这条规则被哪一个物品使用
- 每个槽位当前绑定了哪个属性
- 当前是否启用
- 当前是否缺少必填槽位

---

## 3. 规则启用方式

### 3.1 模式

规则定义新增 `activationMode`：

- `ALWAYS_ON`
  - 规则默认总是运行
  - 不向用户暴露启停开关
- `USER_TOGGLE`
  - 规则允许用户在物品侧手动启停
  - 规则定义保存开关文案与默认状态
  - 规则实例保存当前启停状态

### 3.2 开关 UI 配置

当规则为 `USER_TOGGLE` 时，规则定义还需要保存：

- `labelWhenEnabled`
  - 例如：`计入总价值`
- `labelWhenDisabled`
  - 例如：`不计入总价值`
- `anchorSlotKey`
  - 可选
  - 表示这枚开关更贴近哪个属性输入槽位展示
- `defaultEnabled`
  - 新增该规则实例时的默认启用状态

---

## 4. 属性管理页与物品页的职责边界

### 4.1 属性管理页

属性管理页中的“新建属性 / 编辑属性”只定义属性。

固定原则：

- 不在属性定义里保存真实规则绑定实例
- “添加规则”保留为快捷入口或草稿辅助
- 真正的物品规则绑定发生在物品新增页 / 编辑页

### 4.2 物品新增页 / 编辑页

物品页拆成两个核心区域：

- 属性页
  - 管理该物品拥有哪些属性
- 规则页
  - 管理该物品使用哪些规则
  - 为规则槽位绑定属性
  - 控制规则启停

规则页中如果某条规则缺少必填槽位：

- 规则卡片边框显示浅红提示
- 明确列出缺失槽位

### 4.3 系统业务规则的自动落位

对于系统内置的“业务型规则”，物品页允许按属性上下文自动补出规则实例，而不是要求用户每次从空白开始搭建。

第一阶段采用以下约定：

- 当物品具备 `数量` 属性时，自动补 `计入总数量` 规则实例
- 当物品具备 `购入价格` 属性时，自动补 `计入总价值` 规则实例
- 当物品具备 `扣费周期 / 扣费日` 这类周期属性时，自动补 `周期扣费` 规则实例

这样做的目的：

- 让用户能直接看见“业务关系已经由规则承接”
- 避免旧字段迁移后规则页空白，无法感知效果
- 继续保留用户手动补槽位、启停规则、删除规则的能力

---

## 5. 周期订阅示例

以“周期订阅扣费”为例：

属性：

- `购入价格`
- `扣费周期`
- `扣费日`

规则：

1. `购入价格 -> 计入总价值`
2. `扣费周期 + 扣费日 + 购入价格 -> 周期扣费`

解释：

- `计入总价值` 适合建成 `USER_TOGGLE`
  - 可显示：
    - 启用：`计入总价值`
    - 停用：`不计入总价值`
- `周期扣费` 也适合建成 `USER_TOGGLE`
  - 可显示：
    - 启用：`自动续费`
    - 停用：`暂停续费`
  - 这样用户可以直接控制该物品是否继续参与周期扣费流程

这样可以同时表达：

- 一个属性参与总量聚合
- 多个属性共同驱动周期业务规则
- 规则启停与槽位绑定完全解耦

---

## 6. 当前实现约束

第一阶段先落地以下能力：

- 规则定义支持启用方式与开关文案配置
- 物品规则实例支持启停
- 物品规则页支持槽位绑定完整性提示
- 属性定义不再持久化真实规则绑定

后续可继续增强：

- 将开关显示到锚点属性卡片旁
- 周期规则专用时间调度
- 规则运行结果追踪与调试面板

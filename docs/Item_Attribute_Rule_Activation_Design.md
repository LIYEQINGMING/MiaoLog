# 物品-属性-规则重构与规则启停设计

## 1. 当前正式关系

### 1.1 物品 - 属性

- 物品是属性的集合。
- 属性定义只负责定义字段本身：
  - 名称
  - 值类型
  - 值来源
  - 交互方式
  - 值属性

### 1.2 物品 - 规则

- 规则是物品内部属性之间的业务关系。
- 规则不再从属于某个属性定义。
- 规则实例直接挂在物品上，由物品决定是否启用、槽位是否绑定完整。

### 1.3 属性 - 规则

- 属性通过规则槽位参与规则。
- 某个属性可以被绑定到规则的输入槽位，为规则提供值。
- 某个属性也可以被绑定到规则的输出槽位，接收规则结果。

---

## 2. 规则定义与规则实例分层

### 2.1 规则定义负责什么

规则定义负责描述：

- 规则名称
- 规则说明
- 公式画布结构
- 输入槽位 / 输出槽位
- 槽位值类型
- 槽位值来源
- 输出策略
- 用户开关控制配置
- 周期调度规则

当前正式收口：

- “规则类型”不再作为编辑页核心配置项
- 数据层可暂时保留兼容字段
- 前端编辑时统一按“自定义规则”处理

### 2.2 规则实例负责什么

规则实例负责描述：

- 这条规则被哪一个物品使用
- 每个槽位当前绑定了哪个属性或系统变量
- 当前是否启用
- 当前是否缺少必填槽位
- 当前开关展示在物品的哪个属性下
- 规则最近一次执行状态
- 下一次计划执行时间
- 最近一次生成的调度事件信息

---

## 3. 用户开关控制与触发方式拆分

### 3.1 为什么要拆开

当前正式结论：

- `用户开关控制` 解决的是“这条规则能不能被用户停用”
- `触发方式` 解决的是“这条规则启用后在什么时候运行”
- 规则一旦处于启用状态，就按自身触发器持续运行

因此：

- `USER_TOGGLE` 不再被解释为运行方式
- `始终运行` 不再作为用户可见配置项展示
- 默认计算型规则在启用后自动参与计算

### 3.2 启用控制配置

规则定义继续保留 `activationMode`，但它现在只表示：

- 是否在物品页向用户暴露规则启停能力

语义如下：

- `ALWAYS_ON`
  - 默认启用
  - 不向用户暴露开关
- `USER_TOGGLE`
  - 允许用户在物品页手动启停
  - 规则定义保存开关文案与默认状态
  - 规则实例保存当前启停状态

### 3.3 开关 UI 配置

当规则为 `USER_TOGGLE` 时，规则定义需要保存：

- `labelWhenEnabled`
  - 例如：`计入总价值`
- `labelWhenDisabled`
  - 例如：`不计入总价值`
- `anchorSlotKey`
  - 表示该开关在物品页应更贴近哪个属性展示
- `defaultEnabled`
  - 新建规则实例时的默认启用状态

---

## 4. 触发方式与周期调度

### 4.1 触发方式

当前正式支持的触发方式至少包括：

- `ON_VALUE_CHANGED`
  - 相关输入槽位绑定的属性值发生变化时触发
- `ON_SAVE`
  - 物品保存时统一重算一次
- `SCHEDULED`
  - 到达调度事件时触发

固定原则：

- `ON_VALUE_CHANGED` 与 `ON_SAVE` 属于默认基础触发器
- 这两个基础触发器不在规则编辑页中单独暴露
- 当规则需要“到期触发”“周期触发”“日历触发”时，再额外声明 `SCHEDULED`

### 4.2 周期调度的正式解释

当规则声明 `SCHEDULED` 时：

- 系统需要为它建立调度规则
- 调度规则需要生成日历事件
- 后续运行器消费这些事件执行规则

因此：

- “是否生成日历事件”不再是一个独立可选项
- 它是调度规则的一部分

### 4.3 调度规则来源

周期调度固定支持两类来源：

1. 手动配置日历规则
2. 来自规则槽位

#### 4.3.1 手动配置日历规则

手动配置时，编辑器应允许用户定义：

- 开始时间
- 是否包含时分
- 重复频率
  - 每日
  - 每周
  - 每月
  - 每年
  - 自定义
- 重复间隔
- 每周重复日
- 每月规则
- 结束条件
  - 永不结束
  - 截止日期
  - 发生 N 次
- 时区

#### 4.3.2 来自规则槽位

当调度来源于槽位时，槽位可以承载：

- 开始时间
- 周期单位
- 周期间隔
- 结束条件
- 时区

也就是说：

- 不再只是“某个槽位提供一个调度值”
- 而是按完整调度规则结构进行槽位映射

## 5. 规则定义编辑方式

### 5.1 旧方案不再成立

规则定义编辑页不再采用：

- 变量管理大表单
- 文本表达式为主

因为当前正式方向已经变成：

- 用户在画布上拖拽空槽位
- 拖拽计算符或函数块
- 通过画布拼装公式结构

### 5.2 画布式规则编辑

规则编辑页现在应以“可视化公式画布”为主。

用户可拖拽对象至少包括：

- 空槽位
- 计算符
- 函数块
- 常量块

空槽位放下后，必须弹出配置框，配置：

- 变量名称
- 槽位方向
  - 输入
  - 输出
- 值来源
  - 系统级变量
  - 外部输入
  - 固定值
- 值类型

### 5.3 画布提示系统

画布需要通过颜色、形状、标签、角标来提示：

- 输入槽位 / 输出槽位
- 系统变量 / 外部输入 / 固定值
- 文本 / 数值 / 日期 / 布尔 / 周期单位
- 当前槽位未完成配置
- 当前槽位存在类型问题
- 当前槽位被调度规则引用

---

## 6. 属性管理页与物品页的职责边界

### 6.1 属性管理页

属性管理页中的“新建属性 / 编辑属性”只定义属性。

固定原则：

- 不在属性定义里保存真实规则绑定实例
- “添加规则”只允许作为快捷入口或模板入口
- 真正的规则绑定发生在物品新增页 / 编辑页

### 6.2 物品新增页 / 编辑页

物品页拆成两个核心区域：

- 属性页
  - 管理该物品拥有哪些属性
- 规则页
  - 管理该物品使用哪些规则
  - 为规则槽位绑定属性
  - 控制规则启停

规则页中如果某条规则缺少必填槽位：

- 规则卡片边框显示浅红提示
- 明确列出缺失槽位

### 6.3 系统业务规则的自动落位

对于系统内置的业务型规则，物品页允许按属性上下文自动补出规则实例。

第一阶段采用以下约定：

- 当物品具备 `数量` 属性时，自动补 `计入总数量` 规则实例
- 当物品具备 `购入价格` 属性时，自动补 `计入总价值` 规则实例
- 当物品具备 `扣费周期 / 扣费日` 这类属性时，自动补 `周期扣费` 规则实例

---

## 7. 周期订阅示例

以“周期订阅扣费”为例：

属性：

- `购入价格`
- `扣费周期`
- `扣费日`

规则：

1. `购入价格 -> 计入总价值`
2. `扣费周期 + 扣费日 + 购入价格 -> 周期扣费`

解释：

- `计入总价值`
  - 适合建成 `USER_TOGGLE`
  - 启用文案：`计入总价值`
  - 停用文案：`不计入总价值`
- `周期扣费`
  - 也适合建成 `USER_TOGGLE`
  - 启用文案：`自动续费`
  - 停用文案：`暂停续费`

它的语义拆分如下：

- 启用控制
  - 是否允许用户暂停自动续费
- 触发方式
  - 启用后按 `ON_VALUE_CHANGED + ON_SAVE + SCHEDULED` 运行
- 调度规则
  - 手动配置日历规则
  - 或由 `扣费周期 / 扣费日` 等槽位驱动

---

## 8. 当前实现约束

当前阶段先正式收口以下能力：

- 规则定义支持用户开关控制与开关文案配置
- 规则定义支持 `SCHEDULED` 触发能力的正式建模
- 周期调度支持：
  - 手动配置日历规则
  - 槽位驱动调度规则
- 规则实例支持启停与基础运行时状态持久化
- 物品规则页支持槽位绑定完整性提示
- 属性定义不再持久化真实规则绑定
- 规则定义编辑页采用可视化公式画布

后续可继续增强：

- 将开关准确挂到锚点属性卡片旁
- 周期规则的真正调度执行器与日历事件同步
- 规则运行结果追踪与调试面板
- 画布连线、多分支和高级布局能力

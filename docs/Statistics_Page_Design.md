# 统计页面设计文档

## 1. 文档目的

本文档用于固定“统计页面”的整体设计方案，作为后续以下模块的统一依据：

- 统计页的信息架构与页面定位
- 指标卡、图表区、筛选区、趋势区的组织方式
- 现有图表页面向完整统计页面的演进方向
- 首页摘要数据与统计页深度分析之间的边界

本文档聚焦的是：

- `统计页面为什么存在`
- `统计页面应该回答哪些问题`
- `统计页面如何从当前实现平滑演进`

---

## 2. 统计页面的页面定位

### 2.1 核心定位

统计页面不是首页的放大版，也不是单纯的图表展示页。

统计页面应定义为：

- `个人物品数据分析中心`
- `多维聚合结果查看页`
- `趋势与结构洞察页`

它的核心职责是回答三个问题：

1. 我当前的物品整体结构是什么样的？
2. 我的价值、数量、分类、标签分布有什么特征？
3. 随着时间变化，我的物品世界发生了什么变化？

### 2.2 与首页的区别

首页回答的是：

- `现在大概是什么情况`

统计页回答的是：

- `为什么会这样`
- `结构是什么`
- `变化趋势是什么`

因此固定一条原则：

- `首页做摘要，统计页做分析`

---

## 3. 当前现状与问题

当前已有统计页面已经具备雏形：

- 分类占比图
- 位置分布图
- 月度趋势图

并且已有数据模型：

- 总价值
- 日均价值
- 分类分析
- 位置分析
- 标签分析
- 月度趋势

这说明统计页的数据基础已经存在，但还存在几个问题：

1. 当前页面更像“图表展示页”，还不是完整“统计页”。
2. 核心指标没有形成稳定的摘要层。
3. 标签分析已经有数据结构，但页面中还没有展示。
4. 页面缺少筛选维度，分析还是静态的。
5. 图表之间缺少“解释逻辑”和“分析顺序”。

因此，这份文档需要把统计页从：

- `几张图表`

升级为：

- `指标摘要 + 结构分析 + 趋势分析 + 深入钻取`

---

## 4. 统计页面整体结构

### 4.1 推荐分层

统计页面建议固定为五层结构：

1. `页面头部`
2. `核心指标层`
3. `结构分析层`
4. `趋势分析层`
5. `深入分析层`

### 4.2 推荐页面结构

```text
统计
├── 顶部栏
│   ├── 页面标题
│   ├── 时间范围
│   └── 筛选入口
├── 核心指标
│   ├── 总价值
│   ├── 日均价值
│   ├── 物品数量
│   ├── 分类数量
│   ├── 标签数量
│   ├── 即将到期
│   └── 已过期
├── 结构分析
│   ├── 分类占比
│   ├── 标签分布
│   ├── 位置分布
│   └── 价值贡献排行
├── 趋势分析
│   ├── 月度录入趋势
│   ├── 月度价值变化
│   └── 时间维度切换
└── 深入分析
    ├── 高价值分类
    ├── 高频标签
    ├── 即将到期结构
    └── 可点击钻取列表
```

---

## 5. 页面头部设计

### 5.1 标题

页面标题建议直接使用：

- `统计`

或：

- `数据统计`

不建议：

- `库存分析`
- `仓库分析`

因为当前产品语义已经明确是：

- 物品
- 资产

而不是库存系统。

### 5.2 时间范围入口

统计页建议支持时间范围切换。

第一阶段可以先支持：

- 全部时间
- 最近 30 天
- 最近 90 天
- 最近 1 年

后续可支持自定义日期范围。

### 5.3 筛选入口

统计页建议提供统一筛选入口，而不是在每张图表上各自堆条件。

第一阶段建议支持：

- 分类
- 标签
- 状态

后续再补：

- 位置
- 模板
- 价格区间

---

## 6. 核心指标层

### 6.1 核心定位

统计页顶部首先应该回答：

- 当前总体情况如何

因此必须有一层稳定的数字摘要卡。

### 6.2 第一阶段指标建议

建议优先展示：

- `总价值`
- `日均价值`
- `物品数量`
- `分类数量`
- `标签数量`
- `即将到期数量`
- `已过期数量`

如果页面密度过高，可以第一屏先展示前 4 个，其他折叠到第二行。

### 6.3 指标展示原则

指标卡应满足：

- 一眼可读
- 数字优先
- 文案稳定
- 不和首页资产总览完全重复

首页和统计页都可以展示总价值，但差异应是：

- 首页强调“快速感知”
- 统计页强调“分析入口”

### 6.4 日均价值的定位

`日均价值` 已有明确数据支持，因此建议保留为统计页一级指标。

它的价值在于：

- 衔接首页摘要
- 提供时间尺度感
- 让统计页不仅只有总量，也有变化感

---

## 7. 结构分析层

### 7.1 这一层的职责

结构分析用于回答：

- 我的物品主要由什么组成

因此这里的重点是：

- 占比
- 分布
- 构成

### 7.2 分类占比

分类占比建议继续作为统计页核心图表之一。

建议可视化形式：

- 饼图
- 环形图

适合回答：

- 哪些分类占得最多
- 哪些分类是主力组成部分

### 7.3 标签分布

当前数据结构已支持标签分析，因此统计页第一阶段应补上：

- `标签分布`

它可以帮助用户理解：

- 自己的物品有哪些高频特征
- 当前标签体系是否足够有效

推荐形式：

- 横向条形图
- 前 N 标签排行

### 7.4 位置分布

位置分布建议保留，但文案要偏“存放结构”而不是“库存位置”。

推荐标题：

- `存放位置分布`

它适合回答：

- 物品主要放在哪里
- 哪些位置的物品最多

### 7.5 价值贡献排行

除了“数量分布”，统计页还应引入：

- `价值贡献`

例如：

- 按分类看总价值
- 按标签看总价值
- 按位置看总价值

这会让统计页更像资产分析，而不仅是数量统计。

---

## 8. 趋势分析层

### 8.1 这一层的职责

趋势分析用于回答：

- 我的物品数据是如何变化的

这层强调：

- 时间
- 变化
- 波动

### 8.2 月度录入趋势

当前已有：

- 月度录入趋势

这一能力应保留，作为第一阶段核心趋势图。

它回答的是：

- 哪些时间段录入最活跃

### 8.3 月度价值变化

现有趋势数据已经包含 `totalValue`，因此建议统计页后续增加：

- `月度价值变化趋势`

这样可以从“数量趋势”升级为：

- 数量变化
- 价值变化

双趋势结构。

### 8.4 时间粒度切换

后续建议支持：

- 按月
- 按季度
- 按年

但第一阶段可以先固定：

- 按月

避免复杂度过高。

---

## 9. 深入分析层

### 9.1 为什么需要这一层

如果统计页只有图表，用户只能“看图”，但不能形成行动。

因此需要“深入分析层”，把图表结果转成可进入的分析列表。

### 9.2 推荐内容

第一阶段可先设计但不全部落地，推荐包含：

- 高价值分类排行
- 高频标签排行
- 即将到期分类分布
- 最近新增最多的分类

### 9.3 钻取能力

统计页中的核心模块，后续应支持点击进入对应物品列表。

例如：

- 点击“电子产品”占比 -> 进入电子产品物品列表
- 点击“蓝牙”标签 -> 进入带蓝牙标签的物品列表

这样统计页才不是死图表，而是：

- `分析入口页`

---

## 10. 筛选模型设计

### 10.1 第一阶段筛选维度

建议优先支持：

- 分类
- 标签
- 状态

原因是：

1. 这三个维度最通用
2. 与现有数据结构最容易对齐
3. 对统计意义最大

### 10.2 筛选作用范围

固定规则：

- 筛选条件应作用于整个统计页，而不是单一图表

这样可以保证：

- 所有指标和图表看到的是同一分析上下文

### 10.3 筛选后的表现

筛选后，统计页中的以下内容应同步刷新：

- 核心指标
- 分类结构
- 标签结构
- 位置结构
- 趋势图

---

## 11. 与首页的关系

### 11.1 首页与统计页的边界

首页展示的是：

- 快速摘要
- 高优先事项
- 推荐内容

统计页展示的是：

- 深度分析
- 多维结构
- 趋势洞察

因此应固定：

- 首页可以显示少量指标
- 统计页负责解释这些指标

### 11.2 首页跳转统计页

首页的资产总览或快捷入口，后续应支持进入统计页。

这样用户路径就是：

- 首页看到摘要
- 点击进入统计页看深入分析

---

## 12. 与当前实现的兼容策略

### 12.1 可直接沿用的部分

当前统计实现中，以下内容可以直接保留：

- 分类占比图
- 存放位置分布图
- 月度录入趋势图
- 分析数据模型
- 加载/错误状态

### 12.2 需要补齐的部分

建议补齐：

- 页面顶部核心指标层
- 标签分析图
- 统一筛选模型
- 价值贡献维度
- 图表点击后的钻取能力

### 12.3 命名调整建议

当前类名中还存在 `InventoryAnalysis` 命名，这属于历史技术命名，不代表产品文案。

在产品层和设计文档中，建议统一使用：

- `统计`
- `数据统计`
- `物品统计`

而不要继续使用：

- `库存分析`

---

## 13. 第一阶段落地范围

第一阶段建议完成：

1. 统计页顶部核心指标层
2. 分类占比图
3. 标签分布图
4. 存放位置分布图
5. 月度录入趋势图
6. 基础时间范围入口
7. 基础全局筛选入口

第一阶段暂不做：

- 高级交叉分析配置器
- 用户自定义图表面板
- 复杂拖拽排版
- AI 自动分析结论生成

---

## 14. UI 结构稿

### 14.1 设计风格方向

统计页建议采用当前主流数据分析类移动端 UI 的通用模式：

- `强结构化信息分层 + 卡片式图表容器 + 轻量筛选工具条`

但要避免传统后台报表式的“满屏小图表堆叠”。

推荐组合是：

- 页面背景保持简洁
- 核心指标使用稳定卡片
- 图表区使用统一图表卡片模板
- 筛选和时间范围做成轻量胶囊控件

也就是说：

- 统计页的“高级感”来自信息秩序
- 不来自复杂装饰

### 14.2 页面骨架

统计页建议采用：

- `纵向滚动单列布局`
- `顶部工具条 + 指标区 + 图表区 + 深入分析区`
- `筛选作用于整页`

骨架如下：

```text
┌─────────────────────────────┐
│ 状态栏区域                  │
│ 统计          时间范围  筛选 │
├─────────────────────────────┤
│ 核心指标卡组                 │
│ 总价值  日均价值  物品数 ...  │
├─────────────────────────────┤
│ 结构分析                     │
│ 分类占比图                   │
│ 标签分布图                   │
│ 位置分布图                   │
│ 价值贡献排行                 │
├─────────────────────────────┤
│ 趋势分析                     │
│ 月度录入趋势                 │
│ 月度价值变化                 │
├─────────────────────────────┤
│ 深入分析                     │
│ 高价值分类 / 高频标签 / 钻取  │
└─────────────────────────────┘
```

### 14.3 首屏结构稿

首屏建议优先露出：

1. 顶部标题与筛选工具
2. 核心指标层
3. 第一张主图表的上半部分

这样用户一进入统计页，就能先看到：

- 当前筛选上下文
- 总体数据状态
- 最重要的一张结构图

首屏不建议把过多图表全部塞满，否则会显得像信息墙。

### 14.4 顶部工具条结构

顶部工具条建议采用：

- 左侧标题
- 右侧两个胶囊按钮

推荐结构：

```text
统计          [全部时间 v] [筛选]
```

规则如下：

- 标题使用中等标题
- 时间范围按钮优先显示当前选中状态
- 筛选按钮点击后进入底部抽屉或弹层
- 不建议在顶部同时堆太多筛选 chip

如果后续需要显示当前筛选条件，建议放在工具条下方单独一行：

```text
[电子产品] [蓝牙] [服役中]
```

### 14.5 核心指标层结构

核心指标层建议采用：

- 第一行双大卡
- 第二行四小卡

这是当前很多移动端分析页比较成熟的布局方式，兼顾：

- 核心指标突出
- 次级指标完整

推荐结构：

```text
┌──────────────┬──────────────┐
│ 总价值        │ 日均价值      │
│ ￥128,560    │ ￥352/天      │
└──────────────┴──────────────┘

┌───────┬───────┬───────┬───────┐
│ 物品数 │ 分类数 │ 标签数 │ 到期数 │
│ 128    │ 18     │ 46     │ 3      │
└───────┴───────┴───────┴───────┘
```

规则如下：

- 总价值与日均价值保持同级
- 次级指标全部采用统一尺寸
- 数字比标题更突出
- 每张卡片只放一个重点，不放副段落

尺寸建议：

- 大卡圆角：`20dp` 到 `24dp`
- 小卡圆角：`16dp` 到 `20dp`
- 大卡内边距：`20dp`
- 小卡内边距：`16dp`

### 14.6 结构分析区结构

结构分析区建议采用：

- `1 张主图 + 2 张辅图 + 1 张排行卡`

推荐顺序：

1. 分类占比
2. 标签分布
3. 存放位置分布
4. 价值贡献排行

这个顺序的好处是：

- 先看最大的结构归属
- 再看横向特征
- 再看存放结构
- 最后看价值贡献

推荐线框：

```text
结构分析
┌─────────────────────────────┐
│ 分类占比（主图）             │
│ 环形图 + 图例 + Top3 摘要    │
└─────────────────────────────┘

┌─────────────────────────────┐
│ 标签分布                     │
│ 横向条形图                   │
└─────────────────────────────┘

┌─────────────────────────────┐
│ 存放位置分布                 │
│ 条形图 / 小环图              │
└─────────────────────────────┘

┌─────────────────────────────┐
│ 价值贡献排行                 │
│ 1. 电子产品  ￥52,000        │
│ 2. 收藏      ￥28,000        │
└─────────────────────────────┘
```

### 14.7 图表卡片模板

统计页中的图表卡建议尽量统一模板，避免每张图表一套长相。

建议模板结构：

```text
图表标题              更多/钻取
图表副标题或当前范围说明
[图表主体]
Top 数据摘要 / 图例 / 操作提示
```

统一规则：

- 图表标题在左
- 操作入口在右
- 图表主体高度保持稳定
- 图例和摘要放在卡片下方，不挤在图里

### 14.8 趋势分析区结构

趋势分析区建议采用：

- 上方时间粒度切换
- 下方双趋势卡

第一阶段可先做单列上下结构：

```text
趋势分析
[按月]

┌─────────────────────────────┐
│ 月度录入趋势                 │
│ 折线图 / 柱状图              │
└─────────────────────────────┘

┌─────────────────────────────┐
│ 月度价值变化                 │
│ 折线图                       │
└─────────────────────────────┘
```

如果第一阶段只做一张趋势图，也建议先保留第二张卡片位置语义，方便后续扩展。

### 14.9 深入分析区结构

深入分析区建议采用：

- 列表型分析卡
- 每个模块都可点击进入具体物品列表

推荐结构：

```text
深入分析
┌─────────────────────────────┐
│ 高价值分类                   │
│ 电子产品        32 件  ￥52k │
│ 收藏            8 件   ￥28k │
└─────────────────────────────┘

┌─────────────────────────────┐
│ 高频标签                     │
│ 蓝牙            18           │
│ 通勤            14           │
└─────────────────────────────┘
```

这类卡片比复杂图表更适合承接：

- 钻取
- 排序
- 查看明细

### 14.10 筛选交互结构

统计页筛选建议采用：

- `顶部按钮 + 底部抽屉`

而不是把所有筛选项平铺在页面顶部。

推荐交互：

1. 点击 `筛选`
2. 底部弹出筛选抽屉
3. 用户选择分类 / 标签 / 状态
4. 确认后刷新整页

抽屉内建议按分组展示：

- 分类
- 标签
- 状态

并提供：

- 清空
- 应用

两个明确操作。

### 14.11 图表样式建议

统计页图表建议遵循当前流行的数据可视化移动端原则：

- 背景干净
- 主色控制在 1 到 2 个强调色
- 辅助色用于区分分类
- 线条比传统图表更粗一些
- 不要塞过多网格线和坐标轴文字

具体建议：

- 环形图优先于传统厚重饼图
- 标签分布优先横向条形图
- 趋势优先平滑折线图或圆角柱状图
- 图表阴影轻一点，不做浮夸发光

### 14.12 滚动与吸顶行为

统计页滚动时建议：

1. 顶部工具条轻度吸顶
2. 当前筛选条件行在有内容时可跟随吸顶
3. 图表卡片不做复杂吸顶
4. 深入分析列表区域保持自然滚动

这样可以保证：

- 筛选始终可达
- 页面不会因为过多吸顶而显得压迫

### 14.13 加载、空态与异常

#### 加载态

建议使用：

- 顶部指标卡骨架
- 图表卡骨架
- 趋势卡骨架

#### 空态

当没有足够数据生成统计时，建议显示：

- 核心指标仍显示 `0`
- 图表位显示空态占位
- 引导用户先去添加物品

#### 异常态

统计页失败时不建议整页只剩一个报错文案。

更推荐：

- 保留页面骨架
- 失败模块单独提示
- 提供局部重试

### 14.14 组件样式建议

统计页建议采用：

- 页面左右边距：`16dp`
- 模块上下间距：`16dp` 到 `20dp`
- 主图表卡高度：`260dp` 到 `320dp`
- 次级图表卡高度：`200dp` 到 `240dp`
- 排行卡行高：`48dp` 到 `56dp`

文字层级建议：

- 页面标题：`headlineMedium` 或相近级别
- 图表卡标题：`titleMedium`
- 指标数字：更高一级但不夸张
- 图例与注释：`bodySmall`

## 15. 最终固定方案

当前可固定的统计页面设计方案如下：

1. 统计页面定义为个人物品数据分析中心，而不是单纯图表展示页。
2. 页面结构固定为“头部 + 核心指标 + 结构分析 + 趋势分析 + 深入分析”。
3. 首页负责摘要，统计页负责深度分析。
4. 第一阶段核心指标建议展示总价值、日均价值、物品数量、分类数量、标签数量、即将到期、已过期。
5. 第一阶段核心图表建议包含分类占比、标签分布、存放位置分布、月度录入趋势。
6. 筛选条件应作用于整个统计页，而不是单张图表。
7. 统计页后续应具备从图表结果钻取到具体物品列表的能力。
8. 产品层文案统一使用“统计”语义，不再继续使用“库存分析”作为页面名称。
9. 统计页 UI 结构稿采用“强结构化分层 + 统一图表卡模板 + 轻量筛选工具条”的设计方式。
10. 首屏优先展示顶部工具条、核心指标和第一张主图表，不把所有图表同时塞进首屏。
11. 核心指标采用“双大卡 + 四小卡”，结构分析采用“主图 + 辅图 + 排行卡”，筛选使用“顶部按钮 + 底部抽屉”交互。

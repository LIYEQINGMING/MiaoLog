## 20260714 10:00 规则V1落地：新建规则页的调整
建议：
1. 触发方式的设置，太多也太复杂了，我想其实这个应该不是用户考虑的。因为规则不关联到属性，他就是一个定义。但是如果他关联到了属性，那么就自然就触发了。无论是周期计算、事件触发，还是属性变化触发，这些其实都是自然触发的。如果属性变了，那么自然会触发规则，进行一次新的计算。所以这里进行规则触发方式的设置，是不符合我们对于规则的设计的。
2. 当前的新建规则的页面，对于用户来说太过于复杂了。我想我们需要重新来设计一下UI和UX。大致是这样，用户点击新建规则后。操作流程：设定规则名字+规则说明 → 添加表量 → 可视化编辑器编辑计算公式 → 保存规则。

首先就是填写规则名称和规则说明，不需要顶部那个logo+规则名称+说明的预览。

然后就是槽位配置和计算说明这里，改成可视化公式编辑器，变量（槽位）的添加做成一个添加按钮，然后把现在槽位的那些配置都放到点击“添加变量”后的弹窗里。添加后的变量用于编辑计算公式。有一个按钮或者抽屉可以查看已添加的变量。
变量这里就包含了属性、常量、系统级变量等。

可视化公式编辑器基于 AST（抽象语法树） 作为核心数据模型，采用 Jetpack Compose + MVVM 实现。画布（Canvas）负责节点布局、缩放、拖拽与选中；节点（Node）对应 AST，包含变量、常量、运算符、函数、括号等类型，可递归组合；属性面板负责节点配置，工具栏提供节点创建。通过 Visitor 实现渲染/校验/执行，Command 实现撤销重做，支持文本与可视化双向转换。可参考 Blockly、Node-RED、Power BI Formula、JetBrains MPS。

本次定下来的核心边界

- AST 只负责“表达式结构”，不替代 RuleDefinition 、 RuleSlotDefinition 、 RuleBindingInstance 。
- 变量继续落库为 slots ，AST 里只引用变量，不重复定义变量。
- 常量直接进 AST 字面量节点，不单独建槽位。
- 系统变量继续走 SYSTEM_INPUT 槽位，不绕开槽位体系。
- 输出不进入 AST 赋值语句，仍由输出槽位和 outputStrategies 承载。
- triggerModes 从规则编辑页 UI 移除，但底层模型先保留，保存时继续走默认值。
- MVP 采用“树形 AST 编辑器”，不做自由拖拽 Canvas。
MVP 范围

- 页面流程固定为：名称/说明 -> 添加变量 -> AST 公式编辑 -> 保存。
- “添加变量”弹窗负责新增/编辑槽位，变量本质上是 slots 的友好 UI。
- AST 最小节点集定为： Literal 、 VariableRef 、 UnaryOp 、 BinaryOp 、 FunctionCall 、 Conditional 。
- 本轮只要求 AST -> expression string 单向编译，不做重兼容的“文本 -> AST”双向解析。
- 继续兼容当前运行时链路：绑定页、依赖补齐、规则求值入口都不推翻。

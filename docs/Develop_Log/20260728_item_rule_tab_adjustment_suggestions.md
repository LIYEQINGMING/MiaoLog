## 20260728 物品编辑/新增页规则 Tab 调整

## 修改建议

1. 规则 Tab 既然和属性 Tab 都受物品编辑页/新增页底部“保存修改 / 保存物品”按钮统一控制，那么规则页中的“运行开关”调整，应该同步回流到属性 Tab，方便用户实时预览属性侧最终效果。

2. “已绑定属性”这一栏当前有些多余。既然当前设计下并不能直接在该区域调整绑定属性，那么绑定关系的主操作入口就不应该再放在这里展示。后续规则-属性绑定关系应收口到“计算公式”中的槽位点击交互里。

3. 规则卡中的“计算公式”槽位点击后，应弹出一个“属性选择器 / 属性选择窗”：
   - 属性来源包括：
     - 当前物品已有的常规属性
       - 系统内置属性
       - 用户自定义属性
     - 系统级变量
   - 视觉上可以参考现有的 icon / emoji 选择器思路，但要更轻量。
   - 选项最好直接展示为“属性名 + 属性值”的形式，方便用户理解并做选择。
   - 例如：
     - 公式为：`[] + 当前总数量 = 总数量`
     - 用户点击 `[]`
     - 弹出属性选择浮窗
     - 浮窗中展示当前物品已有属性和系统级变量供选择

4. “计算公式”中的槽位和计算符号，应在同一行内竖向居中，确保视觉上明确是一行公式。当前符号位置偏高，需要统一基线与垂直对齐。

5. 按第 1-4 点调整后，规则卡将不再直接支持“绑定一个当前物品还没有的属性”。为覆盖这类场景，属性选择器中应允许“快捷创建一个新的属性”：
   - 该快捷创建仅需要：
     - 属性名称
     - 值类型
   - 说明默认为空
   - 值来源默认为输入
   - 因为当前属性创建已不再要求先绑定规则，这个流程理论上足够轻量，可以放进属性选择器中完成。

6. 属性管理中的“新建属性 / 编辑属性”页面里，“关联规则（快捷入口）”应删除。
   - 因为在新的交互设计下，属性-规则的实际关联关系，已经转移到物品编辑/新增页的规则 Tab 中完成。

7. “运行开关”需要扩展为“控制规则中用户可操作事项的位置配置”：
   - 将标题“运行开关”改为“运行开关位置”
   - 同行右侧那个总开关去掉
   - 下属内容应展示当前规则卡中可暴露给用户的操作开关
     - 例如：`计入总数量`
     - 例如：`计入总价值`
   - 每一个操作开关右侧应有一个属性槽位框
     - 样式类似“计算公式”中的变量框
     - 但可选范围仅限于“当前公式里已经参与计算、且属于当前物品的属性”
   - 例如公式为：
     - `数量 + 当前总数量 = 总数量`
   - 那么“计入总数量”操作开关的位置槽位，就只能选择：
     - `数量`
   - 用户选择完成后，该操作开关应在属性 Tab 中显示在对应属性下面。

## 实现结果

1. 物品新增页 / 编辑页中的规则 Tab 已按新方案收口：
   - 去掉了旧版“已绑定属性”区块。
   - 规则卡主要保留“规则名称与说明”“计算公式”“运行开关位置”三段。
   - 公式区域改为单行槽位式展示，槽位与运算符做了同一行垂直居中处理。

2. 规则卡中的“计算公式”已改为槽位点击交互：
   - 点击槽位后会弹出属性选择窗。
   - 选择源改为当前物品已有属性为主，并补充系统级变量入口。
   - 选择项展示为“属性名 + 当前值”形式，便于用户理解当前绑定上下文。
   - 旧版跨规则卡片的绑定入口已清掉，交互收口回当前规则卡片内。

3. 属性选择窗中补上了“快捷创建新属性”：
   - 支持最小输入：属性名称、值类型。
   - 快捷创建会直接通过属性仓库落库，而不是只做前端临时假数据。
   - 新创建的属性会即时加入当前物品可选属性集合，并回流到当前槽位绑定。

4. “运行开关”已重构为“运行开关位置”配置：
   - 不再在规则卡上直接放总开关。
   - 改为为规则的用户操作项选择挂载到哪个属性下方。
   - 该位置配置现在落在物品规则实例上，并补了数据库字段与 `64 -> 65` 迁移。

5. 属性 Tab 与规则 Tab 的预览联动已打通：
   - 规则页中调整开关挂载位置后，属性页会按新的挂载属性实时展示对应操作开关。
   - 规则启停仍然走同一份物品编辑状态，因此属性页和规则页预览保持同步。

6. 属性管理页已同步清理：
   - 删除了“关联规则（快捷入口）”区块。
   - 属性定义页重新回到“只定义属性本身”的职责边界，规则与属性的实际关联改由物品页规则 Tab 承担。

7. 根据本轮补充建议，规则选择与持久化链路继续收口：
   - “计算公式”中的槽位卡片已去掉值预览，避免规则卡片本体信息噪音过高。
   - 值预览保留在“属性选择器”内部，用户只在真正选槽位时看当前值。
   - “属性选择器”改成“当前物品属性 / 系统变量”两个 Tab。

8. “属性选择器”中的快捷创建属性已内嵌到“当前物品属性”Tab：
   - 不再额外弹第二层对话框。
   - 创建区改为两行：
     - 属性名称
     - 值类型
   - 创建成功后会直接绑定到当前槽位。

9. 物品属性与规则保存链路补齐：
   - 快捷创建属性后，会同步更新当前页可用属性定义映射，避免“界面能看到，但保存物品时没有真正写入 item custom attributes”。
   - 物品编辑页保存成功后，会主动清理该物品的编辑缓存，避免下次重新进入时被旧缓存覆盖，造成“刚保存的规则/属性又丢了”的假象。

10. 属性页重复渲染系统基础属性的问题已收敛：
   - 补充属性区构建时会排除基础内置字段，避免像“数量”这类字段既在基础区出现一次，又在补充属性区再出现一次。
   - 这也一并修复了“计入总数量”开关挂在数量下方后，属性页出现两个同名开关的问题。

11. 根据最新一轮交互微调，规则 Tab 再次收口：
   - 去掉了规则卡片“计算公式”下方与“运行开关位置”下方的长说明文案，避免卡片正文过长。
   - 系统规则模板说明中的“适合将……”改成直接陈述式文案，例如“数量字段纳入总数量统计”。

12. “属性选择器”中的快捷创建入口调整为轻量触发式：
   - 不再把创建表单直接嵌在“当前物品属性”Tab 里。
   - 改为在列表底部放置“+”入口，点击后再弹出独立的“创建新属性”浮窗。
   - 创建浮窗继续保持两行最小输入：属性名称、值类型。

13. “属性选择器”中的系统变量预览补了一层实时接通：
   - 选择器内部开始观察物品页字段版本变化，系统变量列表会随当前编辑值刷新预览。
   - 对总数量、总价值、当前日期这些常见系统变量补了直接预览兜底，减少“当前还没有值”的假空态。

14. 属性管理页的“属性详情”已按新职责边界做简化：
   - 点击属性后，仅保留：
     - 属性名
     - 属性描述
     - 值类型
     - 值来源
     - 来源模板
   - 旧版“规则绑定”“依赖补齐说明”“操作”三个区块已移除，和当前“属性只定义自身、规则在物品页绑定”的设计保持一致。

15. 属性管理页的属性列表继续做了信息减法：
   - 列表顺序改为按属性名中文拼音序排序，便于在中文属性集里快速查找。
   - 每条属性左侧的圆形图标已去掉。
   - 属性条目中的“来源模板”“规则”“使用：x 个物品”三行已移除，只保留名称、来源/值类型/值来源、值属性摘要。

16. 物品编辑页 / 新增页的规则 Tab 中，“新增规则”入口改为浮窗选择：
   - 不再使用顶部下拉菜单。
   - 点击“新增规则”后，会弹出类似属性选择器的规则选择浮窗。
   - 浮窗数据直接使用当前规则定义列表，与“属性管理 - 规则”页所维护的实际规则定义保持同源。

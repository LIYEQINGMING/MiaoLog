## 20260727 业务开关属性拆分为属性 + 物品规则实例
### 本轮调整

- 把物品页里原先挂在属性字段上的业务开关继续向“规则实例”收口：
  - `单价 -> 计入总价值`
  - `数量 -> 计入总数量`
  - `单价 + 扣费周期 + 扣费日 -> 周期扣费`
- 这次不再只停留在规则模板层，而是让新增页、编辑页、模板应用、旧物品进入编辑页时，都能把对应规则实例自动补到当前物品上。

### 物品新增页

- `AddItemViewModel` 新增了规则目录注册与自动补规则逻辑：
  - 当页面拿到属性定义与规则定义后，会根据当前已选属性自动补系统规则实例。
  - 选择了 `数量` 时，自动补 `计入总数量` 规则。
  - 选择了 `单价` 时，自动补 `计入总价值` 规则。
  - 选择了 `扣费周期 / 扣费日` 时，自动补 `周期扣费` 规则。
- 模板应用、模板元数据恢复、通用新增页初始化，都同步接入了规则目录注册，避免“属性到了，规则页还是空的”。

### 物品编辑页

- `EditItemViewModel` 也接入了同样的自动补规则逻辑，并额外兼容旧数据：
  - 旧 `excludeFromTotalValue / excludeFromTotalCount / autoRenew / subscriptionCycle` 会在进入编辑页时反推出默认规则实例状态。
  - 如果老物品本来就有订阅周期信息，但还没有规则实例，规则页现在会自动出现 `周期扣费` 规则，缺少槽位时会按设计显示红色提醒。
- 编辑页保存时，`UnifiedItemEntity` 的兼容字段不再直接从旧开关字段读取，而是改成由物品规则实例反推：
  - `excludeFromTotalValue`
  - `excludeFromTotalCount`
  - `isSubscription`
  - `autoRenew`
- `applyEntityBackedFields()` 已不再把 `不计入总价值 / 不计入总数量 / 订阅制 / 自动续费` 回填成表单字段。

### 公共能力

- 新增了 `ItemSystemRuleBindingDefaults.kt`，用于根据规则定义 + 属性定义，自动生成带槽位快照的物品规则实例。
- 这样后续如果再新增“系统内置业务规则”，可以继续沿用同一套自动落实例的方式。

### 备注

- 本轮没有本地编译，继续由你本机验证。
- 当前主目标是先把“业务关系由规则承接”的效果做出来，后续再继续细化规则推荐、自动移除策略、以及更复杂的周期计算。
